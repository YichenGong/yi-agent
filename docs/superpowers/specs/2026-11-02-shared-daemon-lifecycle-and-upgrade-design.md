# 共享项目 daemon：客户端生命周期与用户确认的版本切换

日期：2026-11-02
状态：设计草案，待用户审阅；尚未实现
分支：`docs/runtime-lifecycle`

## 1. 已确认的需求与决策

用户可能只运行一个桌面 App，同时运行多个 TUI。默认后台工作不能在所有前端
退出后继续运行；新 App 不能不知情地使用旧构建 daemon。用户允许在提示影响
范围后，点击按钮主动重启共享 daemon。

确定采用：**一项目一数据库、一共享 daemon，按客户端管理后台工作的生命周期，
通过版本提示与确认重启处理升级。** 不采用每个 App/TUI 各建数据库的方案。
以下生命周期保证针对 managed runtime；用户明确暂用旧／手工 unmanaged daemon
时必须显示例外提示，不能称为已完成迁移或已经具备同等退出保证。

- macOS 关闭窗口仍然隐藏窗口；只有 Cmd+Q／真正退出才释放 App 客户端。
- App 退出，必须停止 App 名下的后台工作；仍活跃的 TUI 的工作不受影响。
- 最后一个客户端离开，daemon 有界收尾并退出；插件登记、定时任务和历史记录
  都不能单独成为默认保活理由。
- 数据库、任务历史、报告和交付记录保留；下次启动继续打开原数据库。
- 版本不一致且协议兼容时，允许用户暂时继续使用，界面持续提示。
- 用户可以主动重启为当前 App 携带的 daemon 构建；重启影响当前项目的所有客户端。
- 重启不会自动重放 spawn、消息发送、外部命令或其他有副作用的请求。

本设计中的“项目”是现有 canonical project key 和实际 runtime 目录共同确定的
运行时作用域，不扩大为整台机器。锁与 socket 的唯一键实际以 canonical runtime
目录为准，路径别名必须归一；项目归属另行核对。`YI_AGENT_RUNTIME_DIR` 的现有
显式覆盖继续有效：同一覆盖目录就是同一个 runtime，不因调用项目不同而生成
第二把协调锁。若其中已绑定另一个项目／配置实例，本期拒绝模糊共享，提示用户
换覆盖目录或连接原作用域，不能一边共享数据库一边声称是互不影响的两个项目。
同一数据库不能通过不同软链路径绕开执行锁。

## 2. 当前实现与根因证据

以下路径均相对仓库根目录，符号名是查证入口，不依赖易漂移的历史行号。

| 代码入口 | 当前行为与缺口 |
|---|---|
| `yi-agent-rs/crates/yi-agent-supervisors/src/daemon.rs::spawn_detached` | 使用 `setsid()`、stdio null，刻意允许 daemon 脱离 App 存活 |
| 同文件 `ensure_running`、`is_running` | 按探测复用已有进程；`is_running` 使用请求是否返回，而非构建身份判断 |
| `yi-agent-rs/crates/yi-agent-app-server/src/server.rs::spawn_resident_watch_loop` | 每约 30 秒为登记项目确保 daemon 存活，没有活跃客户端条件 |
| `yi-agent-rs/crates/yi-agent-supervisors/src/watchman.rs::plist_contents` | launchd `RunAtLoad`、`KeepAlive` 可在 App 外启动值守进程 |
| `yi-agent-rs/crates/yi-agent-app-server/src/settings_store.rs::load_watchman_enabled` | 缺省允许值守，旧安装不能只靠改变新代码默认值完成迁移 |
| `yi-agent-rs/crates/yi-agent-subagent/src/attach.rs::probe_runtime` | `Status` 正常即健康，没有构建握手 |
| `yi-agent-rs/crates/yi-agent-store/src/ipc/protocol.rs::IpcResponse::Status` | 只返回事件水位，无构建或客户端元数据 |
| `yi-agent-rs/crates/yi-agent-subagent/src/attach.rs::attach_project_runtime_with_environment` | 可能在客户端进程内启动 daemon，也可能借用其他进程的 daemon |
| `yi-agent-rs/crates/yi-agent-store/src/ipc/daemon.rs::Daemon::start_with_factory` | 独占锁后恢复在途任务、回收孤儿任务，再加载 coordinator；不能简单多起 daemon 共用数据库 |
| `yi-agent-rs/crates/yi-agent-store/src/runtime.rs::detach_application_root` | 已有 root 暂停与持久 detach，但不等于已建立完整的客户端租约和全部后代退出协议 |
| `yi-agent-rs/crates/yi-agent-subagent/src/thread_root.rs` | 已有逐会话 root 和代际失效逻辑，保留其隔离与不重放语义 |
| `yi-agent-rs/crates/yi-agent-subagent/src/lib.rs::DaemonAgentWorkerFactory` | worker 使用 Rust 线程；不能仅靠终态记录／cancel token 证明实际执行已停 |
| `yi-agent-rs/crates/yi-agent-supervisors/src/supervisor.rs::stop_all` | 当前 kill/wait 直接 child，不等于整棵插件进程树都退出 |
| `yi-agent-rs/crates/yi-agent-tools/src/process/manager.rs::shutdown` | 显式支持 on_exit=keep；与 managed 自动回收策略必须区分 |
| `yi-agent-rs/crates/yi-agent-store/src/repository/mod.rs::migrate` | current_version >= LATEST 即返回成功，尚无高版本 schema 拒绝机制 |
| `yi-agent-rs/crates/yi-agent-store/src/ipc/client.rs` | 默认业务请求回复超时 30 秒，不能直接用作 10 秒退出保证 |
| `desktop/src-tauri/src/window.rs::handle_run_event` | 关闭窗口隐藏；本设计不改变这一交互 |

结论：问题不是 SQLite 必须拆分，而是存量 daemon 的默认保活、客户端退出归属、
构建身份和重启接管缺少统一约束。仅增加退出时 `Stop` 会误伤 TUI，并可能被
watchman 立即重新拉起。

## 3. 范围与非目标

### 本期范围

1. 本机共享项目 runtime 的客户端身份、存活租约和退出回收。
2. 新启动的自动管理 runtime 统一使用独立 daemon 进程，避免依附某个 TUI。
3. App 的版本差异提示、影响预览、确认重启、状态展示与失败反馈。
4. TUI 的兼容检查、重启通知及不兼容后的停止重连行为。
5. 旧 watchman、旧 detached／embedded daemon 的安全迁移。
6. 正常退出、宿主崩溃、更新以及多个 TUI 并存的自动化验证。

### 非目标

- 不新增每前端数据库；不允许多个 daemon 并行管理同一库。
- 不保证强杀前最后一段未落库输出能保存，也不撤销已执行的外部副作用。
- 不提供新的无人值守服务模式，也不在本期悄悄改变手工 `daemon start/serve` 的
  公开 CLI 语义。自动启动统一传入内部 managed 模式；显式手工／旧模式视为
  unmanaged，必须标明无自动退出保证。App 不静默采用它：用户只能明确暂用或
  确认迁移为 managed。它占用同一运行锁时不得再起第二个 daemon。
- 不替所有打开的 TUI 自动升级可执行文件。
- 不处理多个前端同时改同一 checkout 的 Git 冲突，继续依赖现有 sandbox/worktree。
- 不允许本地 App 强杀 SSH 远端或其他用户的进程；远端展示能力不足提示，远端
  生命周期与管理员授权另行设计。

## 4. 架构与职责

### 4.1 持久状态、客户端与 daemon 代际

保留现有项目 `runtime.sqlite`。停止、升级和重新打开都复用该库，不删除数据库、
分支或未验收交付来“清理”运行时。复用不改变既有 trace TTL 等保留策略，不能
据此承诺所有观察数据永久保存。

引入互不混淆的身份：

- `client_run_id`：一次 App 或 TUI 运行的随机身份；App 的多个项目连接和会话
  使用同一 App 身份。不能使用易复用的 PID 代替身份。
- `daemon_instance_id`：本次 daemon 启动的随机代际；重启必变。
- `build_id`：表示 **daemon 可执行产物**，不是 Tauri 壳版本或 `dev/release` 标签。
  发布包携带 sidecar 的构建清单；App 以其配套 sidecar 的 ID 为期望值，TUI 以
  自身可执行产物的 ID 为期望值。同一被复制产物 ID 一致；构建输入或配置改变
  必须可区分，不能只用 `git SHA + dirty`。无可验证 ID 则为 unknown。
- 持久 thread/session ID：沿用现有会话身份；与临时 client_run_id 分离。

客户端身份与其 application roots 建立授权绑定。重新打开历史会话时按已有恢复
规则重新 attach；不能因知道 thread ID 就夺取仍由其他活跃客户端持有的 root。
同一身份重连必须提供登记时签发的私密凭据，并更新连接 epoch；旧连接的迟到
EOF／心跳不能注销新连接，旧 daemon 代际的凭据不能授权新代际的业务请求。

### 4.2 daemon 的唯一生命周期管理入口

现有 TUI、App 会话 attach、插件安装、resident 自愈统一调用同一套带版本检查的
bring-up 逻辑。插件不能另走一个无客户端约束的 detached 启动捷径。headless
`yi-agent run` 在运行期间也是真实前端客户端，命令完成即释放；worker、CLI 只读
查询和内部控制请求不是前台客户端。

新 runtime 由独立进程承载：某个 TUI 退出不再连带结束仍服务 App／其他 TUI 的
内嵌 daemon。子进程可以在机制上脱离启动者，但必须遵守客户端租约；这不同于
原先“启动后永久常驻”。

项目侧协调锁串行化“探测—启动／切换”，与 daemon 自身的运行锁职责分离。
两种锁均保留固定 inode，不以删除文件解锁。所有新启动入口都必须先取得协调权、
读取选择的 runtime 构建和数据库兼容信息，再取得运行锁；探测超时不能当作
“无 daemon”，未 bind 的暂态必须在启动总预算内等待或失败。

独立进程启动必须保留原实例的 `YI_AGENT_HOME`、模型目录及必要的有效配置，
不得因改用项目 cwd 而读另一份配置。共享 daemon 的基础配置沿用该实例目录的
配置；会话已有的模型、沙箱、关联根等覆盖按 root 下发，不把第一个启动客户端
的临时权限变成全局默认。配置实例不同的客户端不能静默共用一个 runtime：
明确提示冲突，要求使用既有 `YI_AGENT_RUNTIME_DIR` 指定另一作用域，而非自动建库。

### 4.3 客户端存活

使用独立的生命周期连接登记客户端，并以心跳租约兜底。短 RPC、trace 订阅、
worker 内部 IPC、插件查询和后台探活都不算新的前端客户端。

- 心跳每 5 秒；30 秒未续约判失效。所有期限使用单调时钟；系统休眠／恢复不
  得仅因跨过 wall-clock 时间误回收仍存活的本机前端。恢复后先给一个完整续租
  窗口，明确释放或已核实的宿主死亡不等待此窗口。
- 显式 `ReleaseClient` 立即进入回收；非预期 EOF 标记 disconnected，允许在
  原 30 秒租约内凭据重连，不把一次传输故障直接当作用户退出。
- daemon 初次启动最多等待 30 秒获得首个客户端；尚未登记期间不得运行插件、
  调度或恢复 worker，避免预热自发启动后台任务。到期后退出。
- App 的租约归属于桌面壳本次运行，而不是 app-server 本次 PID。桌面壳维持
  生命周期通道；app-server 重启不改变 client_run_id。桌面壳状态不可由 sidecar
  凭 PID 声称；凭据与续租通道不继承给工具／worker，App 实际退出后残留 sidecar
  不能续租。sidecar 正常退出只 detach 自己的会话接线，不冒充 App 整体退出。
- TUI 由本次 TUI 进程持有通道。EOF、显式释放与租约失效后的回收必须幂等。
- daemon 允许一个前端连接多个项目，各项目独立登记。单客户端断开不得把
  仍活跃的其他客户端注销；只读版本检查和 UI 状态轮询也不能隐式续租。
- App 仅为实际使用的项目持有登记。没有任务的历史项目不能因曾出现在索引里
  永久保活；离开项目且没有后台工作／插件需求时释放，重新进入再登记。

### 4.4 退出预算与桌面壳行为

正常退出先禁止 sidecar 自动重启，再向全部已登记项目 **并行** 发出 ReleaseClient。
桌面壳暂缓最终退出，10 秒为这次客户端退出的全局优雅预算，不按项目逐个累加；
其后最多 5 秒确认或升级安全终止，并记录每个项目结果。正常 Cmd+Q 仍是用户
授权退出，不重复弹出确认；超时不得将其他 TUI 一起杀掉。

崩溃／非预期断连最迟在 30 秒租约到期后启动同一路径，之后同样使用 10 + 5 秒
收尾预算。租约监控、控制通道和这些期限不能与可能阻塞的业务 RPC 共用执行队列。

若无法确认回收完成，记录“退出回收失败”及影响 scope；不得向 UI／日志报告
成功。桌面壳可以在预算到期后结束，daemon 继续执行已开始的隔离回收，但不得
接纳已退出客户端的任何新任务。对 OS 不可中断态等无法强制终止的异常，不作
绝对的无残留承诺，标记故障并阻止相同 scope 的新 worker 重复执行。

## 5. 退出与后台工作的归属

### 5.1 App 与 TUI 的任务

退出某客户端时先原子地停止接入它的新任务，再取得并收尾其全部会话的运行中
后代；孙任务、排队任务、重试、调度及插件代派任务都必须携带可追溯的所有权。
禁止在枚举后、准入屏障前偷偷派生新后代。保留已完成报告、未集成交付和中断
记录；退出中断使用 paused／recovery_required 及明确原因，不能先落 cancelled
再宣称可以原 attempt 恢复。释放运行资源须在 worker 已停止后确认，不抢先释放
仍可能写 worktree 的执行租约；交付／workspace 保留租约按原恢复规则处理。

不得改变其他客户端的 root、worker、权限或任务预算。关闭 App 窗口不触发以上
流程；Cmd+Q、真正退出以及宿主失活才触发。前台 root 的 LLM／工具执行仍由对应
TUI／app-server 收尾；daemon 管其子任务，不能把“daemon 子任务归零”当作前台
工具进程也已停止的证据。

### 5.2 可强制回收的执行边界

现有 worker 在 daemon 内创建 Rust 线程，仅传递 cancellation token 不能强停
卡死线程。若直接杀共享 daemon，会误伤其他 TUI。因而以下是实现前置条件，而
不是当前已有能力：需要一个可按客户端独立终止的 worker 执行进程边界；daemon
保留唯一 coordinator／数据库所有权，worker 执行器通过内部 IPC 汇报，不另开
runtime 数据库、不另建每 TUI daemon。会话正常使用仍共享一个项目 runtime。
这是保证“退出 App 不影响其他 TUI”在 worker 不配合时仍成立的必要机制，不是
可被实施计划省略的优化；不能以只增加取消令牌代替它。

范围提醒：这不是单纯增加版本提示和重启按钮，还涉及执行器进程隔离及生命周期
回收组件。它们不增加数据库，但会增加进程与内部 IPC；此架构成本属于待用户
审阅的设计决策，不能当作用户已经批准的实现细节。若不接受该成本，应缩小
“卡死 worker 也能按客户端强停”的承诺，不能在保留原线程架构时宣称同等保证。

每个项目的生命周期回收者持有客户端租约、控制 socket 与所管理子进程的身份，
不持有数据库／coordinator，也不运行 Agent。它在 daemon 版本切换期间保持
控制通道和租约，故业务 socket 关闭不会把仍活跃的 TUI 误判为全部退出。
新一代复用控制层客户端身份，但需签发绑定新 daemon 代际的 root／业务授权。
回收者和 daemon 都以选定 sidecar 的产物身份为准。更新回收者时，在旧 daemon／
执行器全部退出后，通过受控 exec 交接：选定的控制监听 FD、已登记客户端连接、
协调锁 FD 与私密的匿名交接 FD 显式跨 exec 保留，其余 FD 关闭；匿名 FD 仅保存
所需控制状态（操作 ID、已消费确认、客户端凭据与 epoch、剩余租约），不落磁盘。
新程序先验证交接版本、scope、目标构建和锁，再接管；不能将已过期租约延长为
新的完整租约。业务 daemon 则始终是新代际，root／业务授权重新签发。

交接前只读验证新程序声明支持该 handover 版本；交接后的控制请求按控制通道
总预算处理，客户端允许短暂重试但不重发非幂等业务。交接失败／不支持时明确
要求退出相关前端后完整重启，不强杀 TUI、不继续伪称回收者已更新。没有客户端
时无须 exec 维持控制通道，记录构建选择后退出即可。

每个客户端的 worker 执行器与工具进程必须登记实际进程身份、归属和进程组；
优雅取消超时只能终止该客户端执行器及其托管组。任务状态完成与实际执行停止
是两个信号，只有后者成立才释放运行租约。正常单任务完成只需确认其执行线程／
执行单元及所属工具停止，不要求退出仍运行该客户端其他任务的执行器；客户端
整体回收则必须确认执行器及所属托管组退出。worker 不响应、假报终态、父进程
先退出但子孙仍在，都不能算清理成功。

全部 worker、插件和受管工具的进程创建需要同项目的轻量生命周期回收者管理，
不依赖 daemon Drop；由它持有子进程句柄、登记归属并在允许执行前确认回收责任。
正常时它不调度任务、不持有数据库、不算前端客户端；daemon SIGKILL／崩溃后
负责终止仍存活的受管组，回收完退出；§7 已授权的受控切换不是异常崩溃，回收者
在该流程中继续服务直到切换结束或失败。先确认回收者清理完成，才允许下一代
开始调度；回收者自身失联时，daemon／执行器的独立存活监控停止准入，按登记
清理各自仍能可靠控制的托管组后退出，不把退出父进程当成子孙已停止的证据。
存活客户端进入故障状态，不未经核实就重建。此监控不能依赖可能卡住的 worker
线程。遇到无法确认清理的异常则失败关闭并报告，不假设进程变成孤儿后会自动死亡。

managed runtime 内不允许 `on_exit=keep` 绕过退出策略：该选项在工具入参处明确
拒绝，不能静默保留后台进程或无提示改成 kill。本期保证覆盖产品托管的进程，
不承诺撤销外部服务副作用或追杀用户绕过托管机制主动 daemonize 的任意程序。
这些进程不能通过继承生命周期 FD 意外保活；所有非目标 FD 在 spawn 时 close。

### 5.3 共享插件与项目级自动工作

插件监督和定时触发不能成为虚假的前端客户端。插件安装／持久 enabled 配置与
本次运行需求分开。App 打开对应项目插件面、TUI 显式使用对应插件时才 acquire
运行需求；离开且没有待处理工作，或客户端退出时 release。再次进入按持久配置
重新 acquire，不能仅因最初安装者退出就导致插件下次再也无法启动。

多个客户端可共享无任务的插件查询服务，但每个自动派生任务必须有唯一发起者
client_run_id，不将任务隐式转给仍活跃的其他客户端。App 发起任务在 App 退出
时停止；其他 TUI 的任务保留。项目级自动触发无明确活跃需求时不执行。历史
无来源需求默认不自动运行，界面提供启用动作；有需求但没有已登记客户端也
不得自启动 daemon。最后一个需求撤销后停止对应自动工作。

最后一个客户端退出后，不再接收定时触发、插件自动派生或 resident 自愈；停止
全部项目级后台工作并退出 daemon。离线触发仍遵守既有 schedule 的 skip／显式
catch-up-once 策略，本期不擅自改成全部永不补跑；无客户端期间绝不执行。

### 5.4 最后退出与新连接的竞争

只有“最后客户端退出”或“确认重启”才进入项目级 drain；单个客户端退出只关闭
该客户端的任务准入，不能让仍在使用的 TUI 收到全局 draining。

项目级 drain 后拒绝新任务，告知新连接等待 daemon 结束并重试；不能在清理一半
时把它重新标成健康。协调锁和代际身份保证下一实例只在旧实例及其执行器停止、
运行锁释放后启动；旧实例不得 unlink 新实例的 socket。锁等待、恢复连接和
最小握手必须受总期限限制，不在 UI 主循环或退出事件回调内做无界同步 IPC。

## 6. 版本握手与提示

### 6.1 独立于业务协议的最小身份读取

在执行普通任务请求前，读取身份与兼容能力：build ID、显示版本、daemon 代际、
启动模式（managed 独立／旧独立／旧内嵌／unknown）、IPC 与 schema 兼容范围、
生命周期能力、已登记的业务客户端／pending 升级客户端概览、活动任务及插件数、
重启能力。客户端概览不包含消息正文、API key 或私密登记凭据。

新 managed runtime 使用独立、版本化的本机控制通道，由生命周期回收者托管；
其身份／租约／切换控制不依赖普通业务协议或数据库响应。普通业务 RPC 继续
走原 socket。控制通道包含 identity、登记／续租／释放、预览与切换状态操作，
不提供绕过业务兼容检查直接 spawn 的入口。协议号从 v1 起独立演进；每帧最多
16 KiB、单次控制请求 2 秒超时，整次操作还受全局剩余预算约束。控制通道名
同样遵守现有 103-byte socket 限制和长路径 hash 回退，目录 0700、socket 0600。
影响预览必须返回完整分类计数；详细列表超出帧大小时按同一快照分页，不截断后
冒充完整范围。确认 token 绑定服务端的完整影响快照／revision，不绑定某一页；
分页期间 revision 改变须重新预览。切换以操作 ID 查询进度，不让单个请求阻塞
等待整个 30 秒启动过程；短暂断连只重查状态，不重复执行已消费的确认。

`lease-only` 登记允许新 App 在业务协议不兼容时保持可观察的前台存在，获取提示
并发起升级；它不授权任务，也不会因为仅轮询状态而自动创建。升级结束后必须
完成新业务握手才能 attach root。关闭 App 或取消该项目使用时释放 pending 租约。

现有旧 daemon 不支持控制通道时，先只读探测原协议。只有收到可解析的成功
Status 且确认所需业务契约受支持，才可走标明“旧生命周期不可保证”的暂用路径；
不能因文件存在、连接成功或收到了 Error 帧便断言兼容。无法识别则为 unknown。
元数据文件仅是发现线索，操作前需从控制通道、受管子进程句柄和锁所有权核实
活实例；socket 关闭、超时或权限错误都不构成可直接强杀／重建的证据。

兼容性必须区分协议可解析与具体功能能力；共享功能用能力交集，对不支持的
新字段／操作禁用，不把“协议号相同”当成全部能力齐全。

| 结果 | 行为 |
|---|---|
| build ID 相同且业务／生命周期能力满足要求 | 正常连接 |
| build ID 不同、协议兼容 | 持续提示，允许暂不重启并使用能力交集 |
| 业务协议不兼容、控制通道兼容 | 只允许 lease-only 和升级控制，禁用任务操作 |
| 新业务兼容但旧生命周期能力缺失 | 可明确暂用，持续显示迁移未生效，不承诺退出保证 |
| 版本或兼容性无法确认 | 显示 unknown；无明确兼容证据不放行业务操作，提供手动处理指引 |

不同构建不一定谁更旧。仅有可比较发布版本证据时写“旧版本”；其余显示“版本不一致”。

### 6.2 App 与 TUI 交互

App 当前项目展示非模态、持续的状态提示，内容包括当前／期望版本、可确认的
客户端数和活动子任务／插件自动工作数，按钮为“暂不重启”和“重启为当前版本”。
暂不重启不视作永久忽略；提示保持可发现，按项目和 daemon 代际记录选择，避免
重复弹窗。客户端数按已认证身份去重，重连 socket、内部查询和 worker 不重复计数。

示例：

> 当前项目的后台运行时与 App 版本不一致，部分新功能可能不可用。
> 当前连接：本 App、2 个 TUI；运行中子任务：3 个。
> [暂不重启] [重启为当前版本]

存在其他客户端、运行中／排队任务或插件自动工作时，必须二次确认影响范围；
仅有本 App 且没有上述工作时可在用户点“重启为当前版本”后直接执行，但底层
仍通过预览 token 校验。无法获得完整影响范围时必须二次确认并写明 unknown；
无法安全控制旧进程时，“继续”按钮不得伪装成可执行强制重启。

> 重启将中断该项目全部客户端正在运行的子任务及插件自动工作，包括另外 2 个 TUI。
> 已保存记录与交付 commit 保留；执行中的任务可能需要手动恢复。
> [取消] [确认重启]

预览只读、不暂停现有任务。确认后冻结新任务，显示本项目重启进度；不能为等
待用户确认而持有全局维护屏障。取消／token 到期不改变 daemon 运行状态。

TUI 至少显示构建差异、runtime 即将重启、任务被中断、协议不兼容需升级的文本
状态。本期不要求新增 TUI 的强制重启按钮或另一套管理员操作面。旧 TUI 未实现
通知协议时只能显示“可能中断，无法主动通知”，不能承诺它已收到通知。

## 7. 用户确认后的重启协议

### 7.1 预览与授权

重启是当前用户、当前项目范围的破坏性控制，不注册成可由 LLM 自动调用的工具。
UI 确认由本地桌面壳控制入口承接，不能新增一个任意业务 RPC／远端设备都能
绕过确认调用的强制 kill 入口。同 UID 下运行任意代码不在此机制的安全隔离
承诺之内；不要把“未注册 LLM 工具”误称为 OS 级权限隔离。

影响预览签发一次性、60 秒过期的确认 token，绑定已认证的发起客户端、项目
runtime key、daemon_instance_id、目标 build ID、可用的目标产物、影响 revision。
无控制通道的旧实例由本地桌面壳管理入口维护预览与 token，绑定核实的进程身份、
运行锁及可观察的影响信息，不要求旧 daemon 实现新 token 协议。影响未知须明确
标记；确认不能代替安全停止能力，也不能绕过 §8 要求旧前端手动退出的条件。
revision 覆盖其他客户端的加入／离开、活任务及其执行器、插件运行需求的变化，
不随心跳、日志、token 用量变化，避免持续输出让确认永远失效。

确认时原子校验 revision 并进入维护。影响集合变化则消费旧 token、重新预览并
重新取得确认；锁竞争返回已有切换状态，不能用前一次同意授权另一个实例。
任一新任务入口、插件／定时派生与 root attach 都必须经过同一准入屏障。重启
前已有业务请求，按单次请求语义中断或完成，不能跨代偷偷重发。

### 7.2 状态机与顺序

`idle → preparing → draining → stopping → starting → verifying → ready / failed`

1. 确认前只做只读预检：目标产物存在且可执行、身份清单一致、schema 兼容、
   空间足够进行安全迁移、旧实例可受控停止，必要的旧 watchman／自愈源可冻结。
   预检不操作真实用户任务，不因检查版本而启动另一个 daemon。
2. 用户确认后取得项目协调权，原子校验影响 revision 并进入维护。协调权覆盖
   整次切换；冻结本项目自动拉起及旧管理器的任务准入，通知能接收通知的客户端。
3. 并行请求 worker／插件收尾。10 秒为全部对象的共同优雅预算，不逐对象累加；
   预算包括 IPC 读写与等待。不能复用默认 30 秒业务请求超时冒充 10 秒保证。
4. 优雅期结束仍未停止时，最多再用 5 秒终止并确认目标代际的独立 daemon、
   worker 执行器与托管组。由生命周期回收者依据未丢失的子进程句柄／登记进行
   终止，不能先杀父再按易变化的 PPID 搜后代，也不能按模糊名字批量 kill。
   旧非受管实例缺少可靠身份或回收能力时进入 failed/manual-action-required，
   不伪造自动强杀成功。
5. 旧实例、其执行器或运行锁任何一项仍未退出则失败；不删除锁文件伪造释放，
   不允许新一代调度。停止成功后更新同一 runtime 的受控构建选择记录。
6. 需要更新生命周期回收者时先执行 §5.2 的受控 exec，再由它使用已预检的当前
   App 配套 sidecar 启动 daemon。启动前再次核实产物身份，防止 bundle 在点击后
   被替换。打开原数据库；控制层交接、启动与握手就绪共用 30 秒预算，超时回收
   本次启动的受管子进程，不能留下半启动 daemon。
7. 验证回收者与 daemon 都属于目标 build ID、daemon 代际已变、数据库兼容／
   可读、控制和业务通道以及回收者健康后才报告 ready。兼容客户端重新登记或
   续接已有控制租约并 attach；不兼容的 TUI 明确提示，不自动抢回自己的旧构建。
   解除维护后恢复现有需求，不自动恢复中断任务。

切换期间确认发起者或其他客户端退出，不取消已授权的停旧步骤。控制者不可
用时由存活的生命周期回收者收尾；下一发起者必须重做影响确认，不能继承已
消费 token。若停旧后已无活跃客户端，记录“旧实例已停止，无客户端，新版将在
下次连接时启动”，不为了完成动画启动无人使用进程，也不伪称新版已 ready。

运行时版本切换期间客户端的原生命周期通道继续服务；维护屏障后新来的注册
只获得“等待下一代”状态，不获得旧代际业务授权，也不扩大已经确认要中断的
任务范围。此类等待者若仍活跃，可成为下一代的客户端；它的退出须同样可观察。

### 7.3 错误、恢复与构建选择

- 每个 runtime 在同一状态目录保留原子写入的构建选择记录：期望 build ID、
  产物身份、schema 范围及最后切换结果，不存凭据。该记录是防止自动降级的
  策略输入，不替代进程存活或当前产物身份的核实。首次冷启动在协调锁内建立
  选择记录；仅在无既有运行实例、无先前选择且 schema 兼容时采用启动客户端
  配套产物，不能以“记录不存在”覆盖正在运行的旧实例。成功切换后，即使 daemon
  退出，仍在线的较旧 TUI 也不能用自己的旧二进制自动覆盖选择。目标产物被删
  除或不再匹配时报告需升级／手动重试，不从 PATH 自动回退。
- 普通连接发现已选择不同构建时只连接兼容实例或提示，不悄悄切换版本。用户
  主动选择另一个构建也必须重新预览；schema 不兼容的降级禁止执行。
- 新版启动／迁移失败：显示失败阶段、脱敏原因和重试入口，不静默退回旧版。
  数据库读写范围检查必须在任务恢复、孤儿回收或任何修改之前完成，先用只读
  schema 探测，不调用会执行 migrate／PRAGMA 写入的普通 Repository::open 做
  “预检”。未来 schema 高于本程序可读／可写范围时明确拒绝；不能沿用现有
  `current_version >= LATEST_SCHEMA_VERSION` 即成功的判据。事务迁移失败保留
  原库，若已有不可逆迁移则报告现状，不声称可以安全回滚旧程序。
- 生命周期回收者／控制者崩溃：维护记录带操作 ID 与持有者身份，协调锁可自动
  释放。下一控制者核实锁、执行器和数据库后恢复一致状态，不自动重用失效的
  强杀授权；有残留执行器则先隔离回收，不能仅看到 daemon 锁释放就复活任务。
- 不自动重放旧代际的非幂等请求；沿用 ThreadRoot 的代际失效和单次副作用策略。
  只读查询可在重新 attach 后重试；中断任务按 paused／recovery_required 明示恢复。

## 8. 旧安装迁移

### 8.1 watchman 与 resident 登记

新版首次进入管理路径时，停止并卸载本产品的通用与已知旧标签 launchd watchman，
包括 loaded job 和 plist，避免下次登录复活；保留项目／插件配置和 resident 登记
作为配置数据，但不再将登记解释为无人时应运行。

迁移按实例作用域执行，不按进程名全局清理其他实例的服务；遇到全局旧标签由
多个安装共享、无法判断归属时提示冲突，不静默误卸载别人的配置。必须同时核对
已加载 job 和磁盘 plist 的归属，不能仅按 plist 的文本包含某个路径判定。迁移
失败且旧 watchman 仍可复活 daemon 时明确报告生命周期策略未生效，并禁用自动
强制切换，不能一边允许它复活旧版本一边声称升级已受控。

同时移除本版本 `plugin/install`、设置开关及启动入口自动重装旧 watchman 的行为，
不能“启动时卸载、安装插件时又装回”。旧版本 watchman／旧 app-server 若仍可
忽略协调锁重新拉起，预检提示退出对应旧进程；冻结不成功就不进入破坏性停旧。

### 8.2 已运行的旧 daemon

旧 daemon 没有客户端登记时，不能假装影响范围完整，也不能推断“没有登记 =
无人使用”。标记 unknown，经用户二次确认或手动退出相关前端后才能切换。

- 可确认身份、支持安全停止的独立旧 daemon：走受控收尾与替换。
- 内嵌 daemon：仅请求其宿主退休 runtime、释放锁并禁止再次内嵌抢占，不终止宿主。
- 旧 TUI 不支持退休／退出后禁止重建：提示手动退出对应客户端；不强杀整个 TUI。
- 旧 TUI 即便协议兼容，若尚未实现客户端租约、构建选择与维护屏障，也不具备
  自动重连资格；升级预检必须要求它先退出，否则它可能在新版停机后重新启动
  旧 daemon。新代码无法保证任意旧二进制遵守新增元数据，不能作此承诺。
- 无法核实进程身份、控制协议或同用户权限：禁用自动强杀，提供手动处理指引。

兼容当前业务协议的旧 daemon 可供用户暂时继续使用，但旧进程不具备新生命周期
保证。界面需明确“后台退出管理尚未生效，需重启运行时”，不能只靠新客户端
连接就宣称已完成迁移。

| 组件 | 职责 |
|---|---|
| `yi-agent-store/src/ipc/`、`runtime.rs`、`repository/` | 身份／能力、客户端租约、root 归属、退出与维护准入、只读 schema 预检及持久恢复 |
| `yi-agent-subagent/src/{attach,binding,thread_root,lib}.rs`、`yi-agent-core/src/subagent/worker.rs` | 统一连接契约、版本检查、独立 bring-up、可回收执行器的内部协议、代际刷新及不重放 |
| `yi-agent-supervisors/src/{daemon,watch,watchman,supervisor}.rs` 及生命周期回收组件 | 构建选择／切换协调、独立控制面、执行器与插件进程组回收、旧自愈源迁移 |
| `yi-agent-app-server/src/` | App 状态／预览／确认 RPC、运行时状态通知，不阻塞主请求循环 |
| `desktop/src-tauri/src/{bridge,lib,window}.rs` | App 身份与生命周期通道、真正退出的有界收尾，保留隐藏窗口行为 |
| `desktop/src/` | 当前项目版本提示、影响确认、切换进度和失败展示 |
| `yi-agent/src/` 的 TUI、daemon 与 headless run 入口 | 前台客户端登记、退出回收、版本不兼容提示；工具产生的内部调用不续租 |
| 构建元数据入口 | 向当前前端及其配套 daemon 注入可一致比较的 build ID |

具体接口名与文件拆分留给实施计划，不将本设计中的协议字段描述误当成现有 API。
本期范围虽横跨前端与 runtime，均围绕同一个共享 daemon 生命周期不变量；不得
单独上线按钮，却遗漏版本检查、退出管理或 watchman 迁移。

## 10. 可验证的完成判据

测试使用隔离临时项目、数据库、socket 和假宿主，不操作用户的真实 LaunchAgent，
不调用真实 LLM。基于条件轮询与可控时钟断言，不用固定 sleep 赌时序。

| 场景 | 必须验证 |
|---|---|
| 只有 App，Cmd+Q | App 全部后代／托管进程停止，daemon 退出，库仍在 |
| App 隐藏窗口 | 租约与任务保持，不触发退出 |
| App + 两个 TUI，App 退出 | 只停止 App 任务，两个 TUI 的任务与 daemon 正常 |
| 逐个退出 TUI | 第一个不误伤第二个；最后一个退出完成全量收尾 |
| App／TUI 强杀、生命周期连接丢失 | 残留 sidecar 不续租；租约到期后有界回收；非预期 EOF 不抢先当作显式退出 |
| App-server 意外重启 | 桌面壳仍在时客户端身份不变，不误杀共享任务；旧 sidecar 清理不注销 App |
| 生命周期重连、迟到 EOF／心跳 | epoch 淘汰旧连接，不能注销新登记或恢复已释放客户端 |
| 系统休眠恢复 | 不因 wall-clock 跳变误回收；恢复窗口内可续租；宿主真退出仍可识别 |
| App 多项目同时退出 | 10 + 5 秒是全局并行预算，不随项目数相乘；先禁止 sidecar 重启 |
| 离开空闲项目、headless run 结束 | 释放各自使用需求，历史项目索引与内部查询不永久保活 |
| 首次启动无人 attach、反复并发 attach | 无空进程永久遗留；单 daemon、单运行锁；首客户端前不启动自动工作 |
| runtime 路径别名／共享覆盖目录 | 锁身份一致，错误项目或配置实例被拒绝，不出现同库双 coordinator |
| 同库再次打开 | 读到保留期内报告／历史、交付与中断状态，不重复执行副作用 |
| 相同／不同／unknown 构建、兼容／不兼容协议 | 提示和准入矩阵准确；不同构建不一律叫旧版；旧协议降级不虚报生命周期能力 |
| Tauri 与 sidecar 版本号不同、同 SHA 不同构建输入 | 比较配套 daemon 产物身份，不把 wrapper 号或 dirty 标记误当唯一 ID |
| 业务协议不兼容但控制协议兼容 | 可 lease-only 查看与升级，不能执行任务；控制请求不阻塞退出 |
| 用户暂不重启、取消确认、token 到期 | 不发生 drain／Stop／kill；提示仍可发现，任务继续正常 |
| 重启预览后影响 revision 或代际改变 | 旧 token 被拒绝并刷新，不能误伤未确认范围；日志／心跳不使 token 无谓失效 |
| 大量任务导致预览分页、控制请求短暂断连 | 完整计数与同快照分页不截断影响；操作 ID 查询不重复执行确认；守住帧与请求预算 |
| 同客户端执行器内多个任务、仅一个正常结束 | 只释放已停止任务的运行租约，不退出仍承载其他任务的执行器 |
| 重复点击、两个客户端竞争切换 | 只有一次切换，不出现两个 coordinator 管同一库；已消费 token 不可复用 |
| 维护期间新客户端连接／插件派生 | 新连接等待下一代；原子屏障挡住所有旧代际 spawn 入口 |
| 有活动 TUI 时确认重启 | 范围提示准确；有能力者收到通知并重连；无通知能力不虚报；不兼容者不抢回旧版 |
| 旧 embedded daemon／无新租约契约的旧 TUI | 支持安全退休则只释放 runtime；不支持维护契约则要求退出，不杀宿主 |
| 旧 independent／显式 manual daemon | 不静默采用，不改变手工 CLI 语义；unknown 影响范围必须确认或手动处理 |
| 独立 daemon 无响应 | 超时升级仅命中已核实实例，子进程回收，锁未释放则拒绝启动 |
| worker 忽略取消、假报终态、工具 keep | 按客户端终止执行器不误伤其他 TUI；物理退出前不释放执行租约；keep 明确拒绝 |
| daemon SIGKILL／回收者失联 | 不靠 Drop 清理；受管执行器／插件整组退出，未确认归零不重启调度 |
| 插件父进程先退出，子孙还在 | 检查整组而非仅 child PID；不能留下孤儿工作继续写项目 |
| 新版启动／schema 迁移失败 | 不报告成功、不自动降级、不删库；启动超时清理本次子进程 |
| 库 schema 超出程序支持范围 | 只读预检拒绝，未执行迁移／任务恢复／孤儿回收等写入 |
| 新版退出后旧 TUI 自动启动 | 支持新契约者遵守持久选择；不遵守的新旧混跑必须在预检阻断，不能承诺任意旧程序受约束 |
| App bundle 被替换或目标产物被删 | 启动前身份重核失败，不从 PATH 自动改用其他构建 |
| 控制者崩溃／回收组件自身需要更新 | 不遗留永久维护标记、不复用强杀授权；版本不兼容时提示退出再完整启动 |
| 所有客户端在切换中退出 | 停旧后不遗留无人使用的新进程，状态不伪称 ready；控制通道租约跨业务重启仍可靠 |
| 已装旧 launchd watchman | 注入式验证 loaded job 与 plist 归属、bootout + 卸载、配置保留；插件安装不再重装 |
| 其他项目、实例、用户或远端 | 不被本项目重启／退出操作影响；实例冲突明确报错，不偷偷另建库 |
| 插件／定时任务 | 不计为前台客户端；需求可重新 acquire；最后需求撤销后不再派生任务；保留原离线策略 |

实施阶段提交前在隔离 worktree 的 `yi-agent-rs/` 执行 `cargo fmt --all`、`just ci`，
并运行实施新增的 daemon 生命周期集成测试与受影响的 desktop Vitest 用例。
仅有静态设计文档并不代表这些行为已经实现或测试通过。
