# 会话分组：拖动进出（替换「+」按钮）

日期：2026-10-25
状态：待实现
关联：`2026-10-21-session-groups-design.md`（分组本体）

## 背景与问题

分组框头上现在有一个「+」按钮，点开列出同目录下未归组的会话，再点一条加进去。
实测反馈：**不直观**——它把「把会话放进组」表达成了一次菜单选择，而用户脑子里的
动作是「把这条拖进那个框」。而且它只能加、不能减，移出还得绕到会话右键菜单。

侧栏本来就有 HTML5 拖拽（置顶区重排）。本次把「进出分组」也交给同一个手势，
并把「+」删掉——同一件事只留一个入口。

## 目标

1. 拖动会话行到组框上 → 加入该组。
2. 从组框内拖一条到框外 → 移出该组。
3. 多选时，拖任意一条 = 整批操作。
4. 删掉组框头的「+」按钮及其选择器。

## 非目标

- **不做手动排序**。侧栏顺序仍由服务端 `updated_at` 倒序决定；拖到哪一行上都不
  改变最终位置。用户明确否掉了临时排序方案。
- 不改服务端。分组写操作仍走既有的 `thread/group/setMembers`（整表替换）。
- 不做组框之间的拖动排序、不做跨 workspace 拖动。

## 手势设计

### 整行可拖，但按着修饰键时不拖

原先只有行尾一个 hover 才显形的手柄可以拖。手柄几乎没人发现，现在改成**整行可
拖**，手柄删除。

但整行 `draggable` 与点击多选天然冲突：浏览器在 `mousedown` 后只要有位移就转入
原生拖拽，`click` 不再派发。之前的现场故障（「选三条只显示 2」）虽然后来查明
主要成因是前台会话没进选择集，但这条路径本身是真实的。

因此规则是：

| 按下时 | 行是否 `draggable` | 点击含义 |
| --- | --- | --- |
| 无修饰键 | 是 | 打开会话（既有） |
| Cmd / Ctrl | 否 | 切换选择（既有） |
| Shift | 否 | 区间选择（既有） |

修饰键状态由组件顶层的 `keydown`/`keyup` 维护（`modifierDown`）。按下时整行不可
拖，浏览器就不会把它当作拖拽源，点击语义逐字不变。

置顶区例外：那里整行可拖**始终**成立（它承担重排），且 `dragstart` 走既有的
`dragId` 分支，不受修饰键影响——多选置顶行仍按点击处理，只是拖拽照样能发起。

### payload = 当前选择集

`dragstart` 时快照：

- 若拖动的这条**在选择集里**（`isSelected(id)`，含「空集时前台会话算已选」的
  规则），payload = 全部选中项；
- 否则 payload = 仅这一条（用户拖了一条没选中的行，意图显然只是这一条）。

快照在 `dragstart` 时取一次，拖拽过程中不改。

## 落点与语义

### 拖到组框上 → 批量加入

对每个 payload 里的 id：同 workspace 且不在该组 `threadIds` 里的，追加进去；
已在的跳过（幂等，不报错、不改顺序）。最终一次性 `onSetGroupMembers` 提交整表。

跨 workspace 的落点直接忽略——不弹错，拖拽的失败反馈应当是「没反应」。

### 拖到框外会话行 → 批量移出

落点**只认会话行**（框外的普通行，或在别的组框里的行）。目录标题、组框外的空白
处都不是落点——它们不显示高亮，松手什么也不发生。现状里「拖到目录标题即移出」
的实现随之删掉，理由：目录标题不是会话，把它当落点等于让用户猜。

语义：

1. **目标组 = `dragstart` 那一行所在的第一个组**（与既有「移出分组」菜单项取
   `groupsForThread(id)[0]` 同口径）；
2. payload 里属于这个组的成员，一并移出。

所以多选跨越两个组时，从 A 组拖出来只解散 A 组那一批，B 组的成员不动——「拖出
这个框」就是它字面的意思。结果只影响成员关系，不影响位置：顺序仍由
`updated_at` 决定（本次不做排序）。落点是哪一行都不改变最终位置，它只是「拖出
这个框」的手势落点。

### 高亮

- 组框悬停：框描边高亮（既有 `data-group-drop-active`）。
- 框外会话行悬停：该行显示插入线/描边，表示「松手就移出到这里」。

## 风险

- **整行拖拽吞点击**：靠「修饰键按下即不可拖」隔离，并由测试 1/2 钉住。
- **多选拖拽的 payload 快照时机**：若在 `dragstart` 读 `selected` 之外的派生值，
  可能与渲染不同步。取一次快照即可，测试 4 覆盖。
- **多对多**：一条会话在多个组里时，「移出」只处理 `dragstart` 那一行所在的第一个
  组（与既有菜单项同口径），不静默地把所有组都拆掉。
- **落点收窄**：移出只认会话行。原先「拖到项目组头即移出」的实现要删掉，否则
  用户会以为目录标题是可放置区域。
