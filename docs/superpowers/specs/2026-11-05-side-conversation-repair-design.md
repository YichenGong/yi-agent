## 1. 目标与规格关系

用户报告三个问题：常驻“旁问”模块及横幅累赘；在 `/side` 中留言没有结果反馈；TUI 进入 `/side` 后无法退出。

本设计修复现有功能，不重新设计旁问后端。依赖 [原三端设计](2026-11-03-side-conversation-design.md) 的上下文快照、严格只读工具、临时存储、宿主隔离、协议和资源生命周期。本设计覆盖其 §4.1 的独立按钮例外、§4.2 的常驻继续入口/过期展示、§9 的顶栏与按钮、§10.2 的固定旁问提示条，以及 §12 中依赖上述 UI 的验收要求。其余约束不变；旧计划不是本次修复的执行计划。

### 1.1 完成后的用户体验

- 三端均由 `/side [问题]` 进入，`/btw` 保留别名；无参数只打开，不调用模型。
- 不显示常驻“旁问／继续旁问／查看旁问”按钮、独立模块和介绍性横幅；不预留空白区域。
- 同一聊天区域展示旁问自己的问题、流式答案、工具结果及错误，不重放父历史。
- `/back` 立即返回父会话，保留旁问；`/side-close` 明确关闭，不混同“返回”。
- TUI 手打、粘贴、补全命令均能离开旁问；应用级退出在旁问里仍可用。
- 父任务继续执行，父草稿、附件、审批、落盘和用量不被旁问操作污染。

### 1.2 非目标

不重写 runtime/runner，不新增 RPC、持久旁问、嵌套/多旁问、自动回写、旁问附件上传、写工具或旁问审批；不整体放开手机主会话运行中普通发送；不顺带拆分整个 App/TUI，不升级或替换用户正在运行的应用，不自动合并 main 或加入看板。

## 4. 交互契约

### 4.1 无常驻旁问模块

桌面、手机和 TUI 都不另造旁问标题栏、只读横幅、父状态横幅、TTL 倒计时或常驻快捷操作组。删除不再使用的 `SideConversationHeader` 及专属样式/测试；保留通用消息、错误、确认对话框和输入组件。

当前在旁问时，只在**既有输入框 placeholder 和既有状态栏文本位**标识 `/side`、只读及 `/back`；不增加布局行或固定高度，不复制父状态栏。placeholder 会被草稿遮住，所以状态栏必须同时能标识当前会话，读屏能识别。

**2026-11-08 修订（用户明确要求，覆盖上段「不增加布局行」的约束，仅限返回动作）**：桌面与手机的旁支视图顶部保留**一条**返回条，作为 GUI 上离开旁支的唯一可点出口。原设计只有 `/back` 命令，而标识写在 placeholder 与状态栏文本里——用户一打字，placeholder 就被草稿盖住，于是图形界面上不存在任何可点的返回入口（实测报障即此）。返回条的形状照抄侧栏「+ New thread」：圆角 `rounded-md`、底色 `bg-raised`、`px-3 py-2`、左对齐单行、**宽度跟随侧栏实时宽度**（拖动分隔条时两边一起变），因此它读起来是「同一条主操作」，而不是一条新的系统栏。返回条**只承载返回**：不加只读横幅、父状态横幅、TTL 倒计时或快捷操作组，这些仍在禁止范围内。父等待审批可在该状态位简述，详情和操作只能回父查看。不在父视图展示“可继续旁问”模块；用户通过 `/side` 重入。

错误、同步失败、未确定提交、关闭冲突和权限不足属于操作反馈，不属于要删除的宣传横幅：在现有消息/错误位置按需显示，无事件时不占位。原有 `RuntimeVersionBanner`、父审批和普通缓存提示不在删除范围；父审批的操作 UI 仅在父视图出现。

### 4.2 命令、平台与输入

| 场景 | 行为 |
| --- | --- |
| 主视图 `/side` 或 `/btw` | 打开/重入当前父的旁问；无参数不调用模型；已有旁问不重取上下文 |
| 主视图 `/side 问题` | 打开后向旁问提交一次；不调用父 send/interject/interrupt；已有旁问 running 时拒绝并保留命令 |
| 旁问普通文本 | Idle 可发送到旁问；Running 可编辑，不插话、不排队、不投父 |
| 旁问 `/back` | 纯本地立即返回；断线、同步中、错误、Observe 和 Running 均可用 |
| 主视图 `/back` | 无操作，明确提示已在主会话 |
| 主视图 `/side-close` | 关闭该父的后台旁问；没有则幂等提示；不能因未在旁问视图而简单拒绝 |
| 旁问 `/side` 或 `/btw` | 拒绝嵌套，保留输入；不投给任何模型 |
| `/help`、`/config`、`/usage` | 在旁问中只读取旁问的帮助、固定脱敏配置和用量；TUI 对应 `/cost` |
| 旁问管理命令 | 拒绝并保留输入；TUI 应用退出命令是明确例外 |

命令按完整首 token 匹配，`/back`、`/side-close` 不接受参数；别名、路径和空白规则沿用原 spec。Tab 只补全文本，不发 RPC；明确执行候选与直接提交共用同一命令裁决。

桌面保留 Enter 发送、Shift+Enter 换行和 IME 保护。手机 Enter 始终换行，点击现有输入框主动作执行：精确可执行命令时主动作临时呈现“执行命令”，否则仍按 Send/Stop 规则，不新增独立“旁问”或“命令”按钮。运行中精确 `/back`、`/side-close` 仍可执行；普通文字不能绕过手机主会话 Stop-only。父待审批时输入框的命令入口仍可用，但命令提交不能作出审批决定。

父输入框有待发附件时，进入旁问的命令拒绝并保留命令和附件，不丢弃附件、不把附件带入旁问。旁问输入区不显示附件、模式修改、模型切换或父工具操作。父的已有附件保持原位，返回后恢复。

### 4.3 只读与旧宿主

Observe 端输入区允许本地导航命令和只读帮助/状态命令，不能将整个输入组件 disabled 到连 `/back` 也不可达。在父视图用无参 `/side` 时只执行 `side/list`/`side/readItems` 查看已有旁问，不调用 `side/open`；没有则说明没有可查看旁问。Observe 带问题进入、发送、Stop、续期和关闭均拒绝，服务端权限校验不变。

不支持能力的宿主不展示 side 命令候选；显式键入则说明不支持，不当普通消息发给模型。已经打开的旁问失去连接/能力时仍可本地返回，不能靠未知状态放开写操作。

## 5. 桌面与手机的会话接线

### 5.1 单一当前会话投影

沿用 `ActiveConversation = main(hostKey,parentId) | side(hostKey,parentId,sideId,generation)`。在 App 组合处形成一份带判别身份的当前会话适配值，统一供应正文、输入及状态；必要时抽薄组件/适配函数，不引入第二个 store 或复制业务控制器。

| 数据/操作 | Main | Side |
| --- | --- | --- |
| 正文、错误、同步、用量 | 父 store/session | 精确 hostKey + sideId + generation 的 SideView |
| 草稿与提交锁 | 父会话身份 | 完整旁问身份 |
| 普通发送 | 父 send | `side/turnStart`，绑定来源 client |
| Stop | 父 interrupt | `side/turnInterrupt` + 当前旁问 turnId |
| 状态命令 | 父 slash handler | 旁问 scoped handler |
| 媒体和附件 | 沿用父流程 | `sideItemsForChat`，不传父 `image/read` 能力 |
| 滚动锚点、边界复位、消息展开 | 父身份 | 完整旁问身份；不共用父持久化锚点 |

正文身份、输入身份和动作身份必须一致。目标已丢失/换代时禁发、显示原因或回父，不能仍标识 side 却隐式调用父 send。所有异步动作捕获来源身份和 client；不得通过不带 host 的 `findView(sideId)` 或“当前连接”猜归属。

旁问通知继续按 namespace 在父管线之前路由；旁问正文不进入普通 ThreadStore、会话摘要、未读、排序、搜索、IndexedDB/localStorage transcript 或父 TurnLog。既有父后台订阅和任务可以继续。

### 5.2 创建、切换与草稿收据

命令提交时捕获父身份、原文和草稿修订，创建/对账过程有可见 pending 反馈；不提前生成一条伪造的正常 thread。创建尚未完成时，本地 `/back` 可撤销“完成后进入”的意图，不取消已发创建；切父、切宿主同理。迟到 open 成功只能安装到原身份的 store，不抢当前视图；用户之后可用 `/side` 重入。创建/提交的网络锁仅拦截重复变更，不禁用整个编辑器或本地 `/back`；Creating 时仍能编辑并执行返回。首问在用户返回前已经提交的继续归原旁问；若返回发生在首问尚未下发时，取消自动首问下发并保留问题为原旁问草稿/待处理记录，不在后台发出用户尚未提交成功的问题。

父命令草稿只在对应操作受理后按提交快照条件清除，不能清除用户在 await 期间的新编辑。自动首问明确失败时，把问题正文保留在旁问待发送草稿并显示原因；若已有更新草稿则保留失败提交为独立临时待处理记录，不覆盖新稿。结果不确定时保留同 requestId/text 的 pending，不释放为可再次新建请求的普通草稿。

移除 App 成功后无条件清空 side draft 的路径。成功、失败和不确定三种收据不能仅以一个 boolean 丢失语义；沿用/最小扩展同步控制器的 pending 状态，不新增服务器协议。身份和草稿修订均匹配才清稿。双击或重复 Enter 不重复发送。

### 5.3 结果与错误反馈

受理后显示本轮问题及运行状态；收到 `side/itemUpdated` 后在当前 ChatView 可见并流式更新，不重复追加同一 item。无参进入且无内容时显示普通空态，不伪装成等待模型。

操作错误、模型失败、同步失败和 policy blocked reason 必须在当前操作来源会话可见；不能仅写入 hook/store 后无 JSX 使用，也不能写入父 lastError 充当旁问反馈。返回后错误仍归原旁问，重新进入可查看。

返回条的副标题显示父会话标题（取自侧栏列表，置顶与分组两个来源都扫）；列表尚未到达时为 `null`，此时只显示动作本身「返回主会话」，不编造标题。父标题过长按可用宽度截断，全文放在 `title` 里；按钮的 `aria-label` 固定为「返回主会话」，不随标题变化，否则读屏用户每次听到的名字都不同、无法按名字定位。

保留 `sideSync` 的固定水位分页、连续 seq、终态和同 requestId 对账。旁问可见时的 5 秒尾帧检查按完整宿主/父身份绑定；新建控制器和同宿主重连换 client 后，即使 parentId 未变也须重新应用可见性。后台父/别的宿主不得被误标为可见；卸载/切换清理旧轮询。父订阅合入现有窗口，不覆盖其它运行中父的订阅。

未同步/断线时禁发并解释；响应丢失显示“发送结果待确认”，对账前不生成新 id、不自动重发到父或新旁问。模型响应慢不等于失败，不用任意短超时提前清空状态；已有 runner 超时规则继续有效。

### 5.4 关闭与返回的区别

`/back` 永远不请求停止或关闭。桌面/手机 `/side-close` 沿用服务端条件确认：读取最新状态；Idle 可直接提交 null；Running 显示按需确认对话框。取消确认不关闭、不返回；确认成功后回父。冲突重新读取并由用户确认，不 force 重试，不误停新轮。用户等待确认期间仍可取消/本地返回。

关闭确认必须携带原 hostKey/parentId/sideId/generation/client/turnId，异步读回或用户确认时不能改用当前视图。已关闭/失效的确认不得影响重开后的旁问。只有当前仍显示被关闭的同一旁问且导航修订未变时，成功/已关闭收尾才可回原父；等待中切父、切宿主、返回再重入时，只更新原目标，不抢当前视图。断线不能把返回伪装成关闭成功；失败保留视图与可操作反馈。

## 6. TUI 输入与退出

### 6.1 所有输入事件都按可见会话路由

`Event::Key`、`Event::Paste`、命令补全和滚动统一选择当前可见的 InputLine/HistoryState。Paste 不自动执行，仅插入可见草稿，后续 Enter 按同一分类器提交。旁问中父待审批不能拒绝 Paste，旁问 Enter 不能投父 decision channel；父视图原有审批 Decision/Command 模式保持不变。

补全显示、过滤、Up/Down/Tab/Enter/Esc 必须针对同一可见输入框；切视图立即同步或清理旧候选。旁问候选只含允许的命令及应用退出；不能显示候选却由另一套输入分支忽略。已完整输入 `/back`、`/side-close` 时一次 Enter 执行，不被补全吞成无反馈操作。

### 6.2 明确退出语义

| 操作 | 行为 |
| --- | --- |
| `/back` + Enter | 消费已提交的命令文本，当场改为 Main；保留旁问转录/运行及未被用户改写的会话草稿，不发 interrupt/close，不等 driver |
| `/side-close` + Enter | 当场回 Main，并可靠投递带当前旁问 turn 身份的 Close；旁问真正 Closed 以 driver 帧为准 |
| Esc | 优先关闭弹窗/补全/审批命令编辑；否则只停止当前可见旁问活跃轮，Idle 无操作，不返回、不退出 |
| Ctrl+C 第一下 | 显示既有应用退出确认，并只取消当前可见会话活跃轮；Idle 也进入确认，不切会话 |
| Ctrl+C 第二下 | 未经其它有效输入解除确认时，走全应用退出与统一收尾 |
| Ctrl+Q、`/quit`、`/q` | 全应用直接退出；旁问中不被当问题发送；沿用现有 runner/租约收尾 |

“保留草稿”不表示自动找回用户手动覆盖成 `/back` 之前的文字：键入/粘贴遵循普通编辑规则；成功导航只消费本次命令，不清父草稿，不清其它旁问状态。被拒绝的普通发送/命令须将 `take_submitted()` 消费的原文恢复到 side 输入；本地返回不恢复 `/back` 以免重入后误执行。

应用退出按键优先于普通字符、补全和父审批；runtime 弹窗打开时也不能吞掉 Ctrl+Q/Ctrl+C。Esc 仍优先关闭弹窗，不能被解释为退出应用。其它正常编辑/导航/提交按既有主视图规则解除 pending_quit；两步确认由同一应用状态管理，不能 Main/Side 各留一份陈旧确认。

TUI Close 与 Web 不同：原生独占 runner 沿用命令即确认、立即返回的现有约定，不增加远端关闭确认弹窗。若 Close 通道满/关闭，返回本身仍成功，但必须在主视图显示“已返回，旁问关闭未送达”，保留后台旁问身份可重试；不能忽略 `try_send` 错误并假报已关闭。driver 拒绝或失败同样可见。停止投递失败也须解释，不影响本地返回和应用退出。

后台状态帧、终态帧和旧 generation 迟到帧不能把已返回的用户拉回旁问；用户显式 `/side` 才重入。关闭后重新打开产生新身份，旧帧不能复活旧视图。退出应用复用 `TuiExitCoordinator` 及 main 的统一收尾，取消两路并有界等待，不通过强杀或绕过清理“解决退出”。

### 6.3 TUI 轻量提示

删除占据转录首行的旁问介绍 header，改用现有状态栏预算内的 `/side · /back 返回` 文本；窄屏优先保留会话身份与返回命令，完整帮助用 `/help`。当前旁问错误不能被父费用/运行状态覆盖。普通父视图不增加常驻旁问模块。
