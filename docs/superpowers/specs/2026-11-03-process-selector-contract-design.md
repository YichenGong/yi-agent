## 1. 问题与证据边界

用户报告：`process_read` 的公开参数要求同时填写 `name` 和 `process_id`，运行时却只允许其中一个；将另一字段填为 `""` 仍报错。

| 层级 | 已确认事实 | 证据 |
|---|---|---|
| 当前会话公开定义 | `functions.process_read` 的 `name`、`process_id` 均为非可选字段；`process_kill` 也有同样定义 | 本次会话提供给模型的工具签名；这是会话内观察，不是仓库文件或已保存的线上抓包 |
| 源码反序列化 | read / kill 的两个选择器字段均为 `Option<String>` | `yi-agent-rs/crates/yi-agent-tools/src/process/tools.rs:172–176,245–249` |
| 源码 schema | 共享 schema 只有顶层 `type` / `properties`，没有 `required`；工具、字段说明未写出二选一约束 | 同文件 `:185–186,257–262,303–323` |
| 运行时校验 | 两个 `Some` 一律拒绝；空字符串不是缺省值，仍为 `Some("")` | 同文件 `selector_from_args:291–300` |
| 注册与 provider 转发 | 已检查的路径直接传递 `t.schema()` / `t.input_schema`，未发现补齐 required 的代码 | `yi-agent-core/src/tool.rs:163–171`；`yi-agent-llm/src/openai/types.rs:111–120`；`openai/responses/types.rs:137–147`；`anthropic/types.rs:114–121` |
| 相关历史 | 提交 `2d441457` 为兼容 OpenAI-compatible endpoints 移除了顶层 `oneOf`，保留运行时互斥校验 | `git show 2d441457 -- yi-agent-rs/crates/yi-agent-tools/src/process/tools.rs` |

JSON Schema 中缺席 `required` 表示没有单独必填属性，并不表示全部属性必填。因此，**当前源码并未把两个字段定义为必填**。

已查明报错机制：模型可见签名要求双字段，调用满足此签名后，运行时按字段是否存在拒绝双选择器；空字符串不能解决冲突。

尚未查明公开定义的变形来源：可能是运行实例版本与源码不一致，也可能是仓库外的 schema/工具签名转换。不能将任一可能性写成既定根因，也不能声称添加 `required: []` 已证明能修复当前实例。

## 2. 目标与范围

- `process_read` 与共用契约的 `process_kill` 对模型公开 `name`、`process_id` 为各自可选字段，同时明确二者必须且只能选填一个。
- 调用者只填写所选字段，未选择字段直接省略，不使用空字符串占位。
- 合法单选择器调用能够通过参数校验；没有选择器或同时提供两个选择器仍失败。
- 源码 schema、provider 请求、最终模型可见定义保持一致。
- 保持 read 的 cursor / max_bytes、分页语义、进程管理和 kill 权限不变。

不在本次范围：全局空字符串归一化、进程选择器 API 重构、增加新的工具、改变 read/kill 的权限、扫描未知进程、修复无证据关联的其他工具。当前 session 不承担实现或部署。

## 3. 方案比较与建议

### A. 推荐：分层取证 + 最小契约修复

先找到字段从可选变为必填的第一处边界，修复实际出错的版本或转换逻辑；同时在共享 schema 与工具描述中明确可选及二选一语义。优点是直达真实问题且保留兼容性；代价是需要取得运行实例和外部转换的证据。

### B. 只补 `required: []` 与描述

改动最小，可增强显式表达，但缺席 required 与空列表在标准 JSON Schema 下等价。若外部转换仍强制所有属性必填，或旧实例未更新，该改动无法根治。可作为 A 的契约清晰化措施，不能单独据此宣告问题已修复。

### C. 放宽运行时，将空字符串视为未提供

可能让部分错误签名生成的调用成功，但未修复公开定义，且改变输入语义、掩盖上游错误。双有效选择器依然有歧义，不采用。本 spec 保留现有按字段存在性互斥的行为。

## 4. 实现前必须完成的定位

将同一工具的以下证据按实际生产链路顺序对齐；只保存 schema、版本和必要配置，脱敏密钥、cookie、环境变量与进程输出。

1. **运行实例身份**：记录实际提供工具的进程/服务、二进制路径、版本或可验证的构建提交；若为外部工具服务，记录该服务身份。不得凭当前 checkout 推断运行版本。
2. **源端 schema**：取得该实际实例导出的 `process_read` / `process_kill` schema，比较 `required` 与字段描述。
3. **provider 请求**：核对实际选用的 Anthropic、OpenAI Chat Completions 或 Responses 请求体中的工具定义，不假设本会话一定走仓库内 provider 路径。
4. **模型可见定义**：核对转换之后两个字段的可选标记及二选一说明；定位第一处发生变化的边界。

处理分支：

- 实例源端已将两个字段设为必填：修复实例对应代码或更新到正确版本，再重做全链路检查。
- 源端可选、下游变为必填：修复有证据定位的转换层，不以运行时容错替代。转换层若不在本仓库，交付对应外部修复与验收证据，不能只提交本仓库描述改动并宣布根治。
- 全链路定义已正确：在新会话对合法单字段调用重验，并核对旧会话是否持有启动时的定义。只有证据支持时才将刷新会话/实例列为必要生效步骤。
- 无法取得关键边界证据：保留“公开定义变形来源未定位”的结论；可以交付契约说明改进，但整体修复状态仍为未完成。

**定位门禁**：第 4 节不是预先选定某个修复文件。实施计划必须先交付实际链路证据与“首个变形边界/尚未定位”的明确判定；未定位时不得开始推测性的转换层修改。第 5.1 节的源端契约清晰化及第 6 节的既有行为护栏可独立完成，但它们不能解除 C5/C6 门禁。外部转换修复若超出本仓库访问或变更权限，需交付阻塞原因与所需授权，不能伪造一个仓库内根治方案。

## 5. 目标契约

### 5.1 公开 schema 与说明

保留顶层 object，不重新引入顶层 `oneOf` / `anyOf` / `allOf` / `not` 等既有兼容性测试禁止的组合关键词。

共享 schema 显式写出 `required: []`，作为无单独必填字段的声明；这不是运行时互斥校验的替代，也不是证明外部转换正确的证据。

字段与工具级说明均覆盖：

- `process_id`：可选，来自 process_start / process_list；使用该字段时省略 name。
- `name`：可选，进程唯一名称；使用该字段时省略 process_id。
- 工具整体：必须且只能提供一个选择器，另一字段直接省略，不填空字符串占位。

示例合法调用：

```json
{"process_id":"proc_123"}
```

```json
{"name":"dev-server","max_bytes":4096}
```

不得盲目开启 strict。若实际 provider 的严格模式要求所有属性进入 required，应先核实当前是否使用该模式，以及是否允许按工具关闭严格模式并保留省略字段；不能将两个选择器直接改成两个必填字符串。若该入口确实无法支持本节的公开可选字段契约，需单独提出适配设计并取得评审批准，本 spec 不预先扩大成全局 schema 改写，也不将 nullable 必填字段冒充可选字段验收。当前 `Option<String>` 对 null 的既有兼容行为见下表；标准调用约定仍是省略未选字段。

### 5.2 运行时规则

保持现有 Option 反序列化与互斥规则，不把 `""` 转成 None，不裁剪进程名称、不静默优先选择某一个字段。

| 输入 | 预期行为 |
|---|---|
| 仅有效 process_id | 进入按编号读取/终止的路径 |
| 仅有效 name | 进入按名称读取/终止的路径 |
| 两字段均缺席 | 选择器校验错误 |
| 两字段均为有效字符串 | 互斥错误，不能执行读/kill |
| 有效 name + process_id 为 `""`，或反向 | 互斥错误，不能执行读/kill |
| 仅一个选择器为 `""` | 保持现有按空值查找的失败行为，不变成“缺省选择器” |
| 一个有效选择器，另一字段为 null | 保持现有反序列化为 None 的兼容行为 |
| 两字段均为 null | 没有有效选择器，校验错误 |

## 6. 验收标准

以下均为**待实现验收要求**，不代表已运行或通过。

- **C1 schema 合同**：read / kill 的源端 schema 为 object，两个选择器都未列为单独必填属性，且公开说明包含必须且只能选填一个及省略另一字段；显式 `required: []` 不破坏既有兼容性测试。
- **C2 参数与运行时**：两个工具分别覆盖第 5.2 节输入矩阵。真实创建命名托管进程，read 按 name 和 id 分别读取同一输出；kill 分别使用独立实例按 name 和 id 终止，避免同一实例已退出导致测试失真。
- **C3 拒绝副作用**：双字段（含空字符串占位）与缺席字段的 kill 均不改变目标进程状态；错误路径不默选一个选择器。
- **C4 provider 边界**：对仓库支持的 Anthropic、Chat Completions、Responses 使用 mock 捕获实际请求，断言传输工具 schema 没有把两个字符串都改为必填，而不是只测试转换 helper。
- **C5 实际公开定义**：在本次故障对应的运行入口和新会话中，模型可见签名两个字段均可选，二选一说明可见；保留实例版本和脱敏 schema 证据。源码单测绿灯不能代替本项。
- **C6 故障入口重验**：通过实际公开工具入口，仅传 name、仅传 id 均可读取输出，不再被入口要求补另一个字符串；双有效字段仍返回互斥错误。
- **C7 生效与回归**：记录必要的重新构建、更新实例或刷新会话步骤；执行已有 process 工具兼容性、输出分页、权限等回归。不得为本次验收重启用户正在使用的正式实例而不经授权。
