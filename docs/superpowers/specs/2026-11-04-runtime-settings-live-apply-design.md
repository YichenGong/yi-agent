# 运行参数全会话即时生效设计

日期：2026-11-04

基线提交：`20a0a26c`

状态：设计已完成多轮审查；配套实施 plan 已编写并审查，功能尚未实现。

## 1. 目标与已确认语义

用户目标：修改设置页「运行参数」并保存后，所有会话使用新值，不要求重启应用、后端或会话。

用户已确认「立即」的执行边界：**保存后立即发布，所有消费者在下一个对应的安全执行点使用最新参数；不取消、不重跑已经开始的操作。** 不把下一轮用户输入当成唯一刷新点，正在进行的长任务也必须更新。

术语：

- **用户回合**：一次用户输入到任务结束，可以包含多次模型请求和工具调用。
- **Agent 迭代**：主循环的一次语义 THINK 机会。模型传输重试不新增迭代，压缩调用也不额外计轮。
- **安全执行点**：一个尚未开始的语义操作执行配置刷新事务并取得完整有效快照的边界；本次操作配置由该事务确定。事务从开始刷新到返回快照是一个短区间，读取的线性化点为重新 open 取得完整文件版本（缺文件时为确认缺失），不是解析完成/回调时间。等待 provider 准入尚不算模型操作已经开始。
- **适用消费者**：同实例、运行支持本 spec 的二进制、且实际使用该字段的消费者。默认沙箱、显式覆盖和角色硬限制的例外见 §3、§5。

正常可读的本地存储条件下，必须满足：

1. 保存成功返回后才开始安全点刷新事务的操作，读取本次提交或之后已提交的设置，不能复用启动快照。
2. 刷新事务与保存重叠时，可以在原子替换前 open 到完整旧版本；即使解析/返回快照晚于保存响应，此操作仍可采用该旧版本。返回后不经新的长等待即开始操作；后续新操作重新刷新，不继承这份旧快照。
3. 保存与读取并发时，操作可以采用完整旧版本或完整新版本，不得混用同一批保存中的字段。
4. 排队等模型准入的请求、尚未发出的通知、尚未接纳的子代理不算已开始，必须在等待结束后的实际操作边界重读设置。已开始的模型操作内部重试例外见 §5.2。
5. 设置变更不取消请求、不丢弃流式输出、不重复工具、不清空消息、不重置执行/资源计数、不重建整个 Agent。
6. 空闲会话不必被唤醒：首次后续操作直接读取新版本即可。电源、排队调度和终端标题等无用户操作也要响应的消费者有独立观察机制，见 §6.2。

存储故障时不假装满足即时采用，按 §9 明确降级。

## 3. 范围、不变量与兼容前提

### 3.1 覆盖范围

覆盖同一 `instance_home`、读取同一 `settings.json` 的适用消费者：桌面/手机连接的全部宿主会话，当前未选中标签页、空闲/运行中/恢复会话，各项目 daemon、组长、现存和未来子代理、CLI/TUI/headless Agent，以及临时旁问。未装配的历史会话下次装配读最新动态值，不批量改写历史消息。

- 不同 `YI_AGENT_HOME`、不同机器或不同设置路径相互隔离。配置路径在实例装配时解析成稳定的绝对路径并注入，不能随会话 cwd 或后续 env 变化漂移；测试可显式注入临时路径。
- 本保证需运行本功能版本的代码；旧二进制不会因文件格式兼容自动获得热更新。部署升级和已知旧 daemon 的能力检查按现有版本/运行时握手扩展能力标识；发现不支持者显示升级警告，保存操作本身不偷偷重启它们。不能据宿主支持就宣称未知的外部旧 CLI 也已支持。
- 不建立全实例消费者注册表、不扫描其他进程来收集全体 ACK。本 spec 的成功表示提交及后续采用契约，不表示所有进程已实时确认。

### 3.2 必须保持

- 会话 ID、历史、cwd、关联根、权限决定、模式、工具资源、取消句柄、父子关系和正在执行的工作连续。
- 保留既有显式 override > 真实启动环境变量 > 当前 settings > 默认值优先级，保留各来源原有解析规则；更新不修改进程环境。仅实际存在该 override 的字段报告该来源。
- 模型/provider/凭据、会话级模型选择、reasoning effort 不属于本次更新。现有独立模型更新仍按其原机制工作，本次不能因此额外重建 provider。
- 旁问硬预算和只读约束、父子授权边界、naked 无提示词/无工具模式、沙箱以及终端能力限制，均高于相应运行字段；这些不是普通的“启动配置默认值”。
- inherited 的普通运行默认值不能误当成不可变硬限制；例如旁问的初始 max_turns 不是永久上限，真正的 ManagedRunLimits 才是独立硬限制。

### 3.3 非目标

不跨机器同步、不增加全局配置 daemon、不追溯改变已返回内容、不恢复被压缩的历史、不向对话塞伪造消息、不因保存重启/重建任务，不建立通用会话权限编辑器。正常动态采用不承诺在固定毫秒内打断所有长请求；主动观察间隔的明确上限见 §6.2。

## 4. 方案选择

采用 **共享动态配置源 + 操作安全点读取完整快照 + 每进程可取消观察器**：前者保证运行中的任务和跨进程消费者不漏更新；后者唤醒电源、标题和调度等主动消费者，通知只作加速/显示，不是模型安全点正确性的唯一依据。

不采用“只推送所有前台会话、下一用户回合再刷新”，它漏掉循环副本和 daemon；不采用“取消任务并重建”，它会中断工作并可能重复工具。

## 5. 全部字段的生效规则

当前 `settings::FIELDS` 共 16 个字段。每个字段必须有声明式采用策略、有效值映射和实际消费测试，新增字段缺策略则测试失败。

| 字段 | 安全执行点与采用规则 |
|---|---|
| `agent.max_turns` | 在新的语义迭代开始前、以及首次模型请求的准入等待结束后，检查最新上限。计数规则见 §5.1。降额不取消已开始的模型操作及其工具，增额允许尚未结束的回合继续；已结束任务不自动复活。 |
| `agent.max_direct_children` | 实际创建/接纳占用直接子额度的任务前读取最新值，与父任务有效状态和计数一起原子判断。达到或超过新上限拒绝新增；不杀已有子代理。 |
| `agent.max_resident_subagents` | 每个 daemon 在预留/接纳常驻名额前读取最新值并更新实际协调器；根 Agent 不占额度，既有计数/恢复口径不变。降额不驱逐现存 worker、不清队列；增额要唤醒原队列重试准入，不等新用户消息。不得先构建超额 worker 再补检查。 |
| `agent.system_prompt` | 下一次正常 THINK 请求构造前采用；清空恢复无用户附加指令的默认构造，不是空提示词，也不是丢掉默认/项目指令。压缩摘要和 naked 等专用角色例外见 §5.2–5.3。 |
| `agent.skills_catalog_budget` | 下一次正常 THINK 提示词构造采用新预算，只重建相应目录片段，不重装工具/MCP、不叠加重复目录。交互选择的优先级见 §5.3。 |
| `compact.ratio` | 下一次自动压缩检查采用；按当前会话实际有效模型的上下文长度沿用现有阈值算法重算，不用宿主默认模型长度。保存可以影响本用户回合后续检查。 |
| `compact.user_budget_tokens` | 下一次实际开始的自动/手动压缩采用，触发判断和保留预算来自同一快照；已开始的压缩按原快照完成。 |
| `compact.tool_budget_tokens` | 同上；不只因保存而立即重新压缩刚按旧预算完成的历史，后续本就需要压缩时再按新值执行。 |
| `power.prevent_idle_sleep` | 本地提交立即请求策略重算；跨进程提交由观察器唤醒，不等原 10 秒 tick。不绕过网络/供电/busy 判据，不中断已开始的 OS 调用。 |
| `power.idle_grace_minutes` | 同次电源重算采用，按既有资格消失起点算剩余宽限，不能把保存时间当成新起点无条件续命。 |
| `power.remote_touch_minutes` | 同次电源重算采用，按真实最后远端交互时间判断；保存是否算交互沿用现有请求分类，不人为伪造 touch。 |
| `tui.notifications` | 真正输出通知之前重读。尚在候选/去抖队列的通知不算已发送；关闭后丢弃未发送候选，不在重新启用时补发。 |
| `tui.notification_method` | 真正发送下一通知前采用，与开关/条件取同一快照；不重放旧通知。 |
| `tui.notification_condition` | 下一通知是否可发送的检查前采用，与开关/协议同快照。 |
| `tui.terminal_title` | 观察器在无用户输入时也触发更新。开时输出当前标题，关时仅在本程序确曾设置标题且允许写入时按既有规则清除。tmux/zellij、非 TTY、写失败自禁仍有效，开关不能绕过。 |
| `startup.sandbox` | **明确例外：只影响保存后新建会话的默认档位**，不要求重启。已有会话不变，恢复会话使用固化基线而不是最新默认；旧元数据兼容例外见 §5.4。子代理不能借全局默认扩权。 |

### 5.1 轮次计数和等待

用 `used` 表示本用户回合已开始的正常 THINK 语义迭代数；每个迭代只计一次，传输重试和压缩不额外计轮。准备新迭代时，`used + 1 > latest_limit` 则按现有 `DoneReason::MaxTurns` 正常结束，且不先发一个已无必要的自动压缩请求。

若本迭代需要自动压缩或 provider 准入，等待结束后在第一次正常 THINK 操作开始前重读并复查同一 `used + 1`，不能重复增加计数。首次 THINK 开始时计入一次；一旦开始，它及对应工具结果按原快照完成。降低到 `used` 或更低时，下次迭代检查结束；调高不重置 used。MaxTokens 后按既有语义重启的新迭代仍消耗新一轮。

手动压缩不是旧用户回合的继续，不拿上次已经终止的 used 阻止它；其硬资源限制沿用原机制。

### 5.2 操作、压缩与重试边界

- 正常 THINK：先完成 provider 首次准入等待，再读取动态值、检查轮次、构造请求。随后若无新的长等待，开始此模型操作。取消、刷新失败或 MaxTurns 退出都要释放已取得 lease。
- 自动压缩：检查触发条件时取快照；决定执行到发起摘要请求若又经过长准入/等待，重新检查最新触发条件和预算，并按同一快照复查本用户回合的 `used + 1`。若已超过最新轮次上限，释放 lease 并正常结束，不发尚未开始的摘要；手动压缩仍按 §5.1 处理。已经开始的压缩不取消、不回滚。
- 取得快照后到真正发出首次语义请求前若出现新的长等待（包括提示词派生中的异步等待），等待后必须重新刷新并重建尚未发出的请求，不能用早先构造的请求越过此边界。无长等待的短同步构造使用已取得快照，不要求把每条 CPU 指令与文件提交锁成同一事务。
- 压缩摘要保持专用输入/提示协议，不注入正常 Agent 的用户系统指令或技能目录；只动态更新它实际消费的压缩参数。自动压缩后正常 THINK 是新操作，必须重读。
- 同一模型操作内部为 429/5xx、断流、网络故障等重新发送原请求，继续使用原快照及原重试预算，即使退避后重新取得 lease。不能在一次重试中途替换提示词。语义请求重新构造/进入下一迭代时才取得新快照。
- 不拆开工具调用与结果配对；更新生效不重排/重复工具。独立手动压缩、重建、旁问都要使用同一动态接口，而非另抄一份旧配置。

### 5.3 提示词、技能目录与角色

- 保留现有真实组合顺序：默认指令 → 用户附加指令 → 会话项目指令 → 日期 → 技能目录；旁问的固定策略最后追加。裸模型模式继续无系统提示词、无技能目录。
- 会话装配时保留构造所需的稳定上下文（角色、cwd、项目指令、日期的原有装配语义等）；热刷新只替换用户段及预算相关目录段，不额外引入项目文件/日期的实时同步需求。无相关变化时输出字节稳定，复用目录服务，不重新安装系统 skills。
- SkillsCatalogHandle、外层 set_system_prompt、worker 派生件缓存和 core 内部请求构造必须归一到同一组合入口。旧 base_prompt / budget 不得在下一回合或目录刷新时覆盖新值。派生提示词缓存键需包含实际用户段、预算及策略、目录版本和会话角色，不能只看模型配置。
- 启动交互中“纳入全部”的选择，仅绑定当时的有效预算值与来源。无关字段更新保留此选择；预算值或来源改变（包括从默认改成显式 settings 的同一数字、清空恢复默认）时，该临时选择失效，使用新数值作为上限，不在会话中途询问、不自动恢复旧的“纳入全部”。CLI/env 的显式预算仍按优先级控制有效值。
- 旁问更新普通动态值，但固定只读策略、独立历史及 ManagedRunLimits 不变；不把动态变更当作 lifecycle generation 更换，不使现存旁问 SourceChanged/关闭，也不重置已消耗预算。naked 跳过提示词/目录字段，但仍更新适用的轮次/压缩参数。

### 5.4 默认沙箱与历史恢复

目前 ThreadMeta 不含沙箱基线，必须补足可选、向后兼容的 `sandbox_baseline`，序列化形状为 `{mode: "read-only" | "workspace-write" | "danger-full-access", promotable: boolean}`：记录会话的基础 sandbox 模式及是否允许按原有会话模式提权，不记录凭据，也不把当前 Yolo 瞬时有效值误当基础模式。缺字段表示旧格式；字段存在但形状/模式非法时拒绝激活并显示元数据错误，不当成缺失或套全局默认；read-only 一律不可提权。

- 新会话在激活工具和委派前固化并持久化实际基线；落盘失败则该新会话不进入可执行状态。恢复、fork 派生同一授权上下文和重建路径沿用基线及原有权限模式/根规则，不重新套最新 startup 默认。
- 已有热会话在能够取得实际控制器基线时按同样规则固化；不能根据新的全局默认猜原权限。保存运行参数本身不切换已有权限。此时基线持久化失败应告警并保留可信内存基线，不打断已在运行的任务；该实例内后续重建仍用内存基线，绝不能因落盘失败改用新默认，冷恢复缺记录时才走下述保守兼容策略。
- **旧冷会话缺基线，且无法从受信的运行实例取得实际旧值时**，无法保证精确恢复未知旧值。采用保守 `read-only`、`promotable = false`，明确提示“旧会话缺少沙箱基线，本次按只读恢复；全局默认未用于扩权”，再固化该基线。不是静默套当前默认，也不声称保留了未知原权限。现有显式权限操作仍走原授权入口；本功能不新增通用权限编辑器。
- 已固化基线不受新的 settings 默认影响，但不能绕过当前宿主由真实 CLI/env 或原有父子安全机制施加的显式硬限制。恢复/重建时实际模式取基线与当前显式限制的更严格者（`read-only` < `workspace-write` < `danger-full-access`），可提权必须同时被两者允许；当前显式 sandbox 不允许提权，即使基线原本 promotable。更宽的显式限制也不自动放宽旧基线。可写根继续受原有会话根和父子授权规则约束，不能合并额外根来扩权；如应用了更严格限制，显示实际限制及来源。此处在恢复/合法重建边界求值，不因运行参数保存扫描或打断现存操作。
- 实际子代理权限取固化会话授权及原有父子限制，不取最近保存的全局默认。已有会话用户主动切换模式仍按原规则执行，不由本次设置保存触发。
- 本兼容策略属于新功能部署时对缺失证据的安全处理；已有会话在正常热更新过程中不得被突然降权/中断。

## 6. 配置源、版本、缓存和提交

### 6.1 单一事实来源与读取策略

`<instance_home>/settings.json` 仍是唯一持久化来源，不新增第二份保存运行参数的 preferences 或版本文件。runtime 提供 `LiveSettings` 抽象（实施时可按项目命名调整），core 只接收窄的动态快照接口，不依赖 runtime 或文件路径。

- 一次读取从稳定路径重新 open 文件，读全一个版本；不复用旧 fd 或仅凭 `(mtime, size)` 判定未变化。完整原文相同时复用已解析对象，必要的解析和派生重建有缓存。
- `revision` 是规范化后全部已识别字段及其未设置状态的内容标识，不含 override、未知键或提示词原文；不要求跨重启单调，A→B→A 可复用标识。因此不能用大小比较 revision 判断先后。
- 严格校验 JSON/已识别分组结构及已识别字段，先应用已知旧键映射，再按同一套字段类型、范围、跨字段规则校验；已识别字段非法不能被宽容反序列化默默当默认。未知字段保留但不参与有效值/版本。
- 完整文件按 UTF-8 字节最多 1 MiB。至多读上限再探测一个字节，不能先无界读取。写入也在提交前检查序列化后完整候选大小，不能保存读取方拒绝的文件；更严格的既有上限取更严格者。
- 缺文件视为全部未设置；存在但坏格式/非法字段/不可读/超限按 §9 降级，二者不混为一谈。
- 读取纯粹不写盘、不安装 skills、不创建 daemon。API、模型操作和观察器使用同一验证规则，不能一个接受、另一个静默默认。

### 6.2 缓存防倒退与每进程观察

每进程、每设置路径共享一个配置源。用同一个进程内 refresh gate 串行化**从重新 open、读取、校验到发布缓存**的整个短事务，防止慢旧读取在新读取后覆盖缓存；该 gate 可包含有界小文件 I/O，但绝不跨模型/工具/压缩/目录装配等长 await 持有。操作拿到不可变快照后立即释放 gate，不逐字段重读，也不在每个流式 token 上读文件。

写入锁次序固定为实例写锁 → 本进程 refresh gate；普通读取只持 refresh gate，绝不反向取写锁。发布与观察回调只入非阻塞通知队列，不能持锁等待用户/客户端 ACK。

- 安全点按需重读是模型、通知、子代理准入的新鲜度保证；即便观察器停顿或漏通知也不能复用启动副本。
- 每个有电源、排队协调器或 TUI 标题的进程，启动一个可取消的至多 1 秒观察周期；不必每个会话一个轮询器。可以用文件事件加速，但周期重读兜底，不能只依赖文件事件。
- 一次本地成功提交直接排入一次观察/重算，不额外等待完整观察周期。其他进程写入、合法外部替换、删除文件，在下一观察周期读取并处理，不等原 10 秒电源 tick，不等用户输入或新的 spawn 请求。
- 观察器更新实际协调器并唤醒排队调度，电源更新按同一快照重算三个参数，标题按当前状态刷新。失败与恢复也通知相关宿主诊断/UI。
- “1 秒”是正常调度下的最大轮询等待，不包括正在执行的文件/OS 调用和调度暂停，不声称硬实时；用可控时钟测试，无需真等 1 秒。退出取消观察器，不遗留线程/任务。
- 配置内容相同不重复派生、不 busy-loop。跨进程观察可合并中间提交，只采用观察到的最新版本，不重放已被取代的版本。

### 6.3 写入串行化与提交点

所有受管写入共用 runtime 的同一入口，至少包括：`settings::write` / `write_to`、app-server `settings/write`、web `PUT /api/config`（`yi-agent-web/src/api.rs:137–159`）、迁移 `migrate_env_settings`（`yi-agent-runtime/src/migrate.rs:397–457`）。其他调用此入口的写入自然受同样约束，禁止新建绕过入口的直接写法。

步骤：

1. 首次保存若父目录不存在，先按实例目录既有安全规则创建（Unix 新目录 0700，不擅自改已有目录权限）；创建失败属于提交前失败，不改变设置。然后对稳定实例路径旁的 `.settings.json.lock` 使用进程间文件锁，并串行化本进程写入；等待用单调时钟，最多 5 秒，超时返回结构化错误。锁文件以受限权限创建，锁由文件描述符持有，进程崩溃释放；不按 mtime 超时删除活锁文件、不 unlink/替换锁 inode。
2. 持锁后重读原文；结构损坏/不可读/超限拒绝覆盖。对已识别旧键先映射到规范键，规范新键存在时优先；写出的已知废弃别名删除，未知键保留。特别是清空 `power.prevent_idle_sleep` 时，不能留下 `agent.prevent_idle_sleep` 让旧值复活。
3. 应用本次 patch 后，对完整候选中全部已识别字段做严格校验（含跨字段）；允许 patch 修复既有非法字段，但不能把未修复的候选保存为成功。此处有意收紧原“宽容接受坏旧字段”的写入行为；错误列出需修复键名、不泄露值，不静默覆盖或把用户锁在无诊断状态。
4. 序列化并检查完整候选大小，准备同目录唯一临时文件；以排他创建避免复用旧临时文件。写入、flush、必要的文件同步、0600 权限处理全部在替换前完成。所有可能导致“未提交失败”的步骤均先做完。
5. 同目录原子替换是**唯一提交线性化点**。提交前失败则删本次临时文件、原文件不变、零发布；提交后不得把 chmod、通知或缓存刷新失败伪装成“未保存”。不尝试用旧文件回滚已经提交的版本，不承诺所有 OS/断电条件下的目录持久化事务。
6. 仍按锁次序使本地缓存/观察有序，入队更新事件后释放锁并返回本次提交结果。不对每个会话逐个 ACK，不在写锁内 await 网络通知。若内存发布失败，文件仍为真相，返回已提交结果并记录可见诊断；下个安全点/观察周期重读自愈。

成功响应描述本次提交，不承诺响应传输期间没有其他客户端再次保存。响应丢失/提交后崩溃时客户端重新读取确认，不自动重复任务。没有逻辑字段变化时返回空 changed_keys，可复用 revision，不发逻辑变更通知；别名规范化可改文件而不构成逻辑字段变化。

迁移的“仅填尚未设置字段”必须由受管入口在持写锁重读后作最终判断（例如条件 patch / fill-missing 事务），不能只把锁外筛选出的旧 patch 交给普通覆盖写入。并发用户保存的非空值优先，已存在但非法的值也不得被迁移当成缺失而静默覆盖，需明确诊断。可保留原迁移对单个非法导入值跳过的行为，但每次合法候选仍需完整校验；先成功处理 settings 再重命名 `.env` 的安全顺序不变，不将无关 websearch 文件迁移扩成跨文件事务。

### 6.4 有效值、来源与派生

启动时显式保存 override 和真实环境的已解析来源，不重复执行迁移或重新抓取进程 env，也不把启动时已合并的值当永久 override。按当前快照与这些固定来源求值，复用启动与动态转换的纯规则。

- 被显式来源遮蔽时，保存更新默认设置但不改变该消费者有效值；应报告“已保存，当前宿主仍由显式参数/环境变量覆盖”。
- 恢复默认是删除规范设置键及其废弃别名后重新求值；有 override 仍由 override 决定，否则用当前代码默认，不保留热更新前的旧值。
- 宿主设置页只报告**宿主默认装配上下文**，不代表所有现存会话/daemon/TUI 的有效值；不汇总或泄露其他进程环境。角色/沙箱差异在对应会话诊断体现。
- 压缩阈值从本次会话的实际上下文长度和当前有效 ratio 推导，沿用既有舍入/默认规则并用不溢出的中间计算。max_turns、预算与来源的解析规则同初始装配，不引入第二份默认常量。

## 7. 消费者职责与重建不变量

- **runtime**：配置源、来源合并、提示词组合和采用元数据集中实现，CLI/app-server/daemon 复用；不把模型、cwd、权限等不相关字段一并重载。
- **core**：主循环、首次 provider 准入之后、自动/手动压缩真正消费动态接口，不能只在 run 前改外层配置。可采用窄 trait/闭包，保持不依赖 runtime 的分层。
- **app-server / CLI / daemon**：工厂、恢复、派生 worker 都注入同一来源。现有因 MCP、权限、模型等其他原因重建 Agent 的路径必须保留该动态绑定、显式来源和角色上下文；不得重建一次就悄悄退回静态配置。WorkerRefresh 模型缓存不变时也必须能采用新运行参数，不重建 provider 才能刷新它们。
- **子代理控制**：直接子上限更新真实 Supervisor；常驻容量更新真实 ResourceCoordinator。配置读取、父状态检查、名额判定/预留在同一受保护的准入步骤中完成。已取得名额的接纳视作已开始，保存不撤销；排队未获名额者在真实授予时重读。队列 fairness、deadline、释放、根计数隔离按原规则。
- **旁问**：保留独立历史、provider 身份、生命周期 generation 与安全预算；动态 settings revision 与生命周期标识分离。正常运行字段可变，真正硬上限取更严格者，不因保存刷新父来源而强制重置旁问。
- **电源**：收到观察事件后重算 busy/远端资格及最新设置，再唤醒 PowerGuard；不只改一个无人消费的配置对象，不等 10 秒 ticker 才把三个值传给电源线程。
- **TUI**：发送通知前读快照、观察标题、保持终端安全限制；`/config` 展示当前有效来源及实际禁用原因，不继续把启动快照当当前值。
- **诊断**：`config/read` 对属于本 spec 的运行字段使用当前宿主有效默认值，不相关配置仍沿原机制脱敏返回；会话权限/模型不因该展示刷新改变。

## 8. 协议和界面契约

### 8.1 精确的兼容扩展

旧输入不变：`settings/write` 接收 `{patch: Record<string, string | number | null>}`；未知键或非法值仍是错误，空串/全空白串与 null 按原约定删键。

支持本功能的 `settings/read` 响应保持原 `fields` / `path`，新增：

- `live_apply_version: 1`：能力版本；缺失不代表支持。
- `revision: string`：本次返回设置快照的内容标识。
- `snapshot_origin: "current" | "last_known_good" | "startup_fallback"`。
- `health: {state: "healthy" | "degraded", code: string | null, invalid_keys: string[]}`；正常 code 为 null、列表为空。错误不含设置值。
- 每个 field 新增 `apply_policy: "next_safe_point" | "next_session"`、`host_value: string | number | null`、`host_source: "override" | "environment" | "settings" | "default"`。host_value 是该字段对应的宿主有效默认值，布尔选项仍用既有 "true"/"false" 字符串；system_prompt 为 null 表示没有用户附加段，不返回拼装后的完整提示词。它不是某个已有会话的生效值。

支持本功能的 `settings/write` 成功响应：

`{ok: true, live_apply_version: 1, revision: string, changed_keys: string[], apply_policy: Record<string, "next_safe_point" | "next_session">, overridden_keys: Array<{key: string, source: "override" | "environment"}>}`。

changed_keys 只列逻辑设置变化，apply_policy 和 overridden_keys 只描述这些键；后者仅针对响应宿主默认上下文。未改变的有效值可能仍受角色硬约束，不能仅凭该列表为空就承诺全体进程无例外。

不变量：保存成功只表示提交，不是全体已采用。write 响应的 revision 是本次提交版本；后续 read 可能已经更新到另一版本。旧服务器缺 live_apply_version 时，新客户端只显示“已保存”，不能显示全会话热更新保证；旧客户端忽略新增字段仍可读写。

新增通知 `settings/changed`，params 为 `{revision: string, changed_keys: string[]}`，无提示词原文。宿主本地提交和观察到其他进程的合法变化都发通知（同版本去重）；可合并变化，不能把通知次序或 revision 字符串大小当作跨进程提交顺序。收到通知后重新 read 当前值。健康状态变化复用该通知作为失效提示，可有相同 revision、空 changed_keys，客户端读取 health 判断。

### 8.2 前端并发与草稿

- `runtimeSettings.ts` 解析保留能力、来源、策略、版本和健康状态；新字段缺失按旧协议处理，不臆造支持标识。
- 每次读使用本地请求序号，丢弃较早请求的迟到响应。保存期间到达的通知合并为后续重新读取；不能用可重复的内容 revision 推断响应先后。
- 后端持锁合并 patch，不同键并发保存均保留，同键最后提交胜出。前端仍只提交本地用户改过的字段。
- 其他客户端/观察器更新时，未编辑字段更新到最新值；已编辑字段保留草稿，提示有远端变化。比较基线分别维护，不能把新读到的值全当成本地改动再次回写。
- 保存只清除本次提交且保存期间未再次编辑的字段草稿。保存期间的新编辑必须保留；保存后再 read 不能无条件 draftsOf 覆盖它们。
- 页面关闭/重开或重连都会 read；通知丢失也能恢复。读取失败保持草稿，并显示错误，不能显示旧成功提示掩盖后续 read 失败。

### 8.3 文案

一般成功：`已保存；支持热更新的同实例会话将在下一个安全执行点采用，通常无需重启。` 配套固定说明：“显式启动覆盖、角色安全限制和默认沙箱的例外见各字段。”不使用“所有会话均已采用”。

默认沙箱说明：`仅影响保存后新建会话；已有会话使用固化基线。旧历史缺少基线时按只读恢复并提示。` 同批包含沙箱时成功提示明确补此例外，不笼统说所有参数都立即改变。

被宿主显式来源遮蔽的字段逐项显示覆盖来源。degraded 显示“配置读取异常，当前使用最后有效值/启动回退值，尚不能保证采用新设置”，并显示安全错误类别和需修复键名。

手机与桌面共享元数据；终端通知设置仍仅在有意义的设置入口显示。未保存草稿和可见错误不能被自动刷新抹掉。

## 9. 失败与降级

- **校验/取锁/写入/提交前替换失败**：返回结构化错误，整批零提交、零逻辑变更通知，原文件及当前有效快照不变。保留现有 invalid_setting / settings_corrupt 等错误分类，增补锁超时、超限类别，不把设置值拼进错误或日志。
- **已提交后的缓存/通知失败**：不返回“未保存”或回滚旧文件；按已提交响应处理，记录受控诊断，读取事实来源自愈。客户端断线不能成为 app-server fatal error。
- **运行期已识别字段非法、坏结构、超限或读取失败**：整份候选不采用，保留最后有效快照并显式告警，不静默降为默认。失败状态不得推进为新成功版本；修复后在下个安全点/观察周期自愈，去重警告并清除恢复状态。
- **启动即无有效快照**：为兼容旧行为，可对已在上限内读取的原文使用已有宽容启动归一化规则得到初始值；不可读/超限时仅以固定来源和默认值回退，不能另调无界旧 load_from 绕过读取上限。必须标记 startup_fallback / degraded 和可确定的非法字段列表（无有效原文时为空），不能把它当成功读过的原文件。后续合法保存采用严格规则并恢复健康。
- **缺文件**：健康的“全部未设置”，按来源/默认求值。外部直接删文件可触发此语义，不当成读取失败。
- **提示词等派生刷新失败**：相关模型操作发出前以可恢复错误收口、释放准入 lease、保留有效历史和工具配对；不偷用旧提示词继续请求。下个显式回合可重试，不自动重放工具，不影响其他会话。已产生历史压缩不因后续刷新失败回滚。
- **容量降低超过占用**：正常受限，不回滚保存、不杀任务、不负数/溢出；只阻止新的超额准入。
- **外部手工非原子改文件**：不提供与受管保存相同的原子提交保证；看到非法中间态按上述降级，合法完整内容恢复后再采用。已知旧键按映射兼容，未知键不执行。

新错误日志/通知仅包含路径、键名、内容标识和受控错误类别，不包含提示词、API key 或配置原文；相同错误去重，恢复后再次故障才重新提示。

## 10. 验收矩阵

测试使用临时实例路径、mock provider、可控制屏障/时钟；不得读写正式配置、调用真实 LLM 或靠固定 sleep 猜顺序。每个安全点测试要明确安排“等待/操作已开始 → 保存成功 → 后续安全点”，观察真正的请求/名额/终端输出，而非只测 JSON 写读。

实施完成时：按 crate 跑相关回归（runtime / core / app-server / subagent / CLI-TUI / web）并控制并发；桌面用现有 test script 检查解析/设置页；执行 `cd yi-agent-rs && cargo fmt --all && just ci`，合并结果按项目要求重跑。人工至少覆盖两项目、一长任务、一空闲会话、一现存子代理、桌面/手机保存、缺基线历史及独立实例。新测试尚未实现，本 spec 不把它们描述成已经通过。

## 11. 完成判据

1. 全部 16 字段有真实采用接线，列入范围的新版本消费者不依赖启动副本；默认沙箱、角色限制、显式来源和旧二进制例外清楚可见。
2. 正常存储下满足 §1 安全点契约，所有受管写入与读取同一套规则；并发、防缓存倒退和提交前/后错误边界正确。
3. 活跃任务无隐式取消/重放/状态清空，配对、额度计数、权限、旁问生命周期及已有资源不变量保持。
4. T01–T28 有自动化证据、关联回归及仓库门禁通过，人工验收范围如实记录。
5. 项目管理状态随实际实现更新；设计阶段统一在 runtime 登记一个未实现需求，相关模块交叉引用，不重复计数。

## 12. 文档与实施边界

本 spec 替代“运行参数仅在启动时生效”“电源保存只能等待下一定时 tick”的旧约定，补足保留会话权限所需的历史基线；不替代模型清单热更新和既有显式权限授权规则。当前范围内没有自动重启或通用权限管理扩展。

后续 plan 分为共享配置源、core 操作边界、提示词/重建、准入/观察器、历史基线、协议/UI 与跨进程验收。写入方和实际消费点清单以 §2、§6.3、§7 为下限，不能将覆盖真实路径的检查推迟到“以后再补”。本次不实施这些任务。
