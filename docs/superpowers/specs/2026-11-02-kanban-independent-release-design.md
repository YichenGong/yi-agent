# Superpowers 看板独立发布与插件宿主设计

日期：2026-11-02

状态：本文已完成多轮设计复查，用户已要求将 spec/plan 合入 main 并加入 Superpowers 看板。本文定义目标，不表示能力已经实现；技术验证和子协议审阅门槛仍须通过。

## 1. 目标、范围与术语

Superpowers 看板作为官方插件独立发布。界面、执行程序、skill 不进入主程序发布物；用户能在不更新 yi-agent 应用包的情况下安装、更新和卸载看板。源码可以暂时留在同一仓库，独立发布不要求先拆仓库。

首版仅支持官方可信插件。支持平台以官方目录明确列出的、经过正式构建及端到端验收的 OS/架构矩阵为准；缺少对应产物时拒绝安装，不要求用户现场编译。当前插件使用 Unix socket / flock，不能仅凭打出 Windows 包就宣称支持 Windows。

术语：

- **桌面客户端**：显示宿主导航和插件 iframe 的应用，可以连接本机或远端。
- **执行宿主**：实际管理项目、会话、插件后端的 yi-agent 实例；本地和远程使用同一管理模型。
- **实例**：按现有 `YI_AGENT_HOME` / `paths::instance_home()` 解析的状态域，不等同于 OS 用户目录。
- **发布版本**：同一 ID、版本和发布摘要绑定的界面、平台程序、skill 与数据兼容声明。
- **激活代次**：实例内某插件发布版本每次激活/切换产生的不可复用运行标识；即使重新激活同一版本，也不复用旧标识。
- **项目授权代次**：某项目每次启用、停用或变更授权时递增的独立标识；只让该项目旧绑定失效，不影响其他项目。运行绑定包含宿主身份、发布摘要、激活代次、项目和项目授权代次。
- **项目**：经用户确认的规范化根路径；worktree 归属由宿主已有项目机制解析，不能仅按 cwd 或字符串前缀猜测。

原则：主程序认识扩展能力、不认识看板业务；完整版本统一激活；安装与项目启用分开；后台常驻与模型任务执行单独授权；页面隔离不代表原生程序沙箱。

不在范围内：第三方市场、账号/评价/付费、任意远程网页、无人值守自动更新、模型上下文热替换、原生程序完整沙箱、跨 OS 用户的统一账户限流。

## 3. 架构与职责

### 3.1 主程序

负责官方发布目录、包验证、兼容性、实例版本管理、项目授权、受管进程、视图容器、能力桥、更新事务、状态及卸载。

导航和设置由插件声明，主程序保留通用外层。新增插件不需要添加“插件名 → 组件”映射。桌面和 TUI 中既有看板专属入口迁移为通用插件能力；终端功能通过插件 CLI/通用命令入口提供，不要求在 TUI 渲染网页，也不借本次任务引入完整终端 UI 插件框架。

主程序允许持有插件 ID 作为数据，不允许以某个 ID 写业务分支、专属路径或专属状态判断。随主程序分发的系统 skill、功能开关注册、帮助文本、资源和测试依赖均须审计，不能只检查主页面 import。

### 3.2 插件

拥有主页面、设置页面、前端状态、看板业务后端、调度、数据格式及迁移、skill。前端独立构建，不共享宿主内部 React 实例、业务 store、CSS 类名或私有组件。主题通过稳定令牌同步，首版不建大型组件库。

插件业务方法自包含于插件包，宿主不解释卡片语义。宿主提供通用授权和任务执行能力，不因“插件可信”绕过已有工具权限、模型审批或合并确认。

### 3.3 两类清单

- **发布清单**：经签名包绑定的静态声明，是版本、入口、能力和兼容性的权威来源，安装检查不执行代码。
- **运行描述**：兼容已有 supervisor / driver 的启动与查询信息；只可由已验证版本产生并受宿主授权约束，不得扩大静态声明中的能力、改用外部 executable 或自行切换版本。

受管 supervisor 通过宿主的通用启动入口解析当前激活记录，不永久绑定某个版本文件的旧绝对路径。刷新不能将托管入口改写回插件自报路径；没有有效实例注册与项目授权时，不运行托管程序。

既有用户自定义 supervisor 的一般行为不在本次重写范围内；但旧看板清单不能作为新插件权限凭据或与受管看板并行启动。

## 4. 界面加载与技术验证门槛

选择独立静态 Web 应用，通过隔离 iframe 加载；不动态导入 React 组件，不建设复杂 UI 描述语言。正式版不依赖开发服务器，资源绑定已验证发布版本。

实施第一阶段必须验证 Tauri/WebView 的资源协议或受控本地资源服务与 sandbox、CSP、原生权限的组合。具体传输机制以验证结果为准；安全要求不是待选项。

必须满足：

1. 页面不能读宿主 DOM、存储、内部 JS、其他插件资源或其他版本资源。
2. 页面不能直接调用 Tauri invoke、原生 opener、文件对话框等主窗口能力。
3. 资源只来自当前包的静态文件白名单；不执行服务端脚本，不提供任意文件读取。
4. 禁止插件自行联网、顶层跳转、弹窗、子 frame、表单外送以及远程脚本/样式/图片等隐式外送；桥是唯一业务通道。CSP 限制须覆盖这些资源类型，而不只是 `connect-src`。
5. 资源服务不可被任意其他网页用于读取本机包或调用桥；资源令牌不包含项目路径、宿主认证信息，不放入可外送日志。
6. 正式构建中正常加载，无开发端口依赖；主题、中文输入、滚动、键盘/焦点和面板尺寸可用。
7. 明确验证 frame 内异常、持续阻塞脚本及大量分配场景下的故障边界。iframe 不等于独立渲染进程，不能仅靠主页面 JS watchdog 保证可恢复；宿主原生侧必须能关闭/重建失控插件容器，使核心交互可恢复且会话持久化不受损。若所用 WebView 无法满足，则技术验证不通过，改用更强隔离容器并重新审阅，而不是默默降低要求。首版不承诺恶意资源耗尽下零卡顿或硬 CPU/内存配额。

iframe 页面视为潜在失控客户端。消息绑定实际 frame、一次性初始化通道及激活代次；不信任页面自报身份，不以 `origin == "null"` 作为信任判断。防止导航后复用初始化、其他 frame 冒领以及重放。

若隔离无法满足，不得通过关闭沙箱、开放任意原生权限解决。调整容器机制并重新审阅受影响的设计。只有 mock 测试通过不足以解除这一门槛。

## 5. 发布包、兼容性与信任

每个受支持平台发布完整包，包含静态清单、`ui/`、平台 `bin/` 和 `skills/`。同一版本的各平台包必须绑定同一界面/skill 内容摘要，平台程序可不同。不要求用户安装 Rust 或 Node.js。

发布清单至少声明：包格式版本、ID、版本、目标 OS/架构、执行宿主 API 范围、桌面界面 API 范围、主视图与设置入口、程序和 skill 入口、必需/可选能力、必需工作流依赖、数据读写版本与迁移描述。

ID、版本、入口均校验为合法且无歧义的标识或包内相对路径；拒绝重复 ID、重名路径碰撞及未知必需字段/包格式。远端执行宿主兼容不等于本地桌面兼容，两端分别检查。插件依赖宿主新能力时允许要求宿主升级，不能承诺任意版本永远独立可用。

原版 skill 不要求安装时改写。受管调用信息由宿主以独立上下文提供，签名包内文件保持不变。

发布信任要求：

- 宿主和桌面内置官方信任根/目录入口，而不是内置插件列表。目录内容与包身份必须被认证。
- 签名覆盖明确的原始 payload 字节，绑定 ID、版本、平台、包摘要、大小、兼容范围及发布序号；实现采用成熟签名库，不自造密码算法。
- 校验公钥不能由下载到的包自行替换。支持签名元数据中的有效期、密钥撤销/轮换和发布撤回；信任根更新须由已有信任授权。
- 记录已接受的发布序号，拒绝无授权回放旧目录。普通更新不降级；显式回退是受控独立动作。
- 元数据过期、签名未知/无效、撤回命中或系统时间异常导致有效期无法验证时，不安装/激活新版本。网络故障不停止已有运行版本；无法确认最新撤回状态时明确标注离线，不声称已验证“当前未撤回”。
- 本地导入仍要求官方签名及可验证的发布元数据；过期或缺失时拒绝，不提供“忽略签名继续”。离线导入不是绕过信任的途径。

已安装且已验证版本在元数据过期或离线时可按既有授权重启和加载匹配缓存，不把普通重启当成新版本安装；激活新发布版本仍需有效元数据。已知撤回的版本阻止新的程序启动和自动任务，明确提示活跃回合的处理选择，不静默强杀用户任务。每次激活、缓存重新采纳及进程启动须核对受管文件的内容完整性和路径边界；已安装文件损坏则不可执行/加载。此检查用于防止损坏和非预期替换，不声称抵御拥有同用户任意执行权的攻击者。

签名格式的序列化字段及桥报文 JSON schema 属于后续协议子 spec，必须在对应实现前审阅并用契约测试固定，不能由实施者临时选出不同解释。本设计已固定语义和安全不变量。

macOS 等平台的原生签名、公证与下载隔离属性需在真实下载后端到端验证。官方包的密码学校验不代替 OS 可执行策略；不得要求用户手工移除 quarantine 或禁用 Gatekeeper。

## 6. 发现、安装与项目授权

设置页提供“已安装”和“官方插件”。前者展示版本、目标宿主、启用项目、状态及生命周期操作；后者展示介绍、来源、能力、兼容性和安装。

安装步骤：获取认证元数据 → 检查执行宿主兼容性及发起安装的桌面兼容性（若有）→ 下载到临时目录 → 验证完整性与来源 → 安全解包/结构检查 → 写入不可变版本目录 → 原子提交已安装记录。首次安装可将该版本设为选中版本，但不产生任何项目运行授权。同 ID/版本不得用不同摘要覆盖；同摘要重复安装是幂等操作，下载/安装与更新共用生命周期锁和磁盘配额。无桌面的安装不因缺少桌面而失败，后续客户端连接时检查自身兼容性。

解包只接受规范化普通文件和目录，拒绝链接、设备文件、绝对路径、`..`、大小写碰撞及重复条目。宿主设置压缩包大小、解压总量、文件数和单文件上限；使用支持限量的解包方式，不相信归档头声明。下载和包解析有超时、取消及磁盘不足处理。入口不得越出包根，原生程序权限由宿主受控设置。

安装只注册插件管理信息。运行视图、skill 和后端在项目启用前不可使用；用户可查看宿主渲染的插件介绍和静态清单信息，不能靠查看插件详情执行插件脚本。首次进入业务视图时引导选择项目。

启用时：规范化项目 → 显示原生程序信任提示与所需能力 → 确认项目授权 → 检查依赖/冲突 → 注册托管运行入口 → 启动并健康检查。失败回滚本次授权/登记，保留已安装包和旧数据。权限记录存入执行宿主实例管理区，不信任仓库内文件自报授权。

权限分别表达：访问项目后端/读取业务数据；修改插件队列等业务数据；发起自动模型任务及修改项目；修改同用户整机配额；后台常驻。前两项构成基本看板使用授权，后三项独立确认，不把配额修改与常驻捆绑。未授权自动执行时可查看与管理队列，但宿主拒绝 driver 发起新任务。已有工具审批与用户合并确认不受影响。后台常驻是宿主级显式选择，多插件共享时按请求者管理。

这些授权约束受管协议和正常插件行为，不是 OS 文件权限沙箱。首次执行原生插件前必须明示它以当前 OS 用户权限运行；用户授权的是官方原生代码的信任，不能用“只读视图”暗示已限制其任意本机文件访问。

能力增加的更新须对受影响项目重新确认；不得沿用旧授权自动扩大能力。必需能力未获批则该项目不切换运行版本：首版只有一个实例激活版本，因此整个更新等待处理，不让各项目混跑版本。

项目授权基于规范路径和宿主身份，不向子目录、同名路径或其他宿主隐式传播。worktree 必须能解析回已授权项目，手动新建且未登记的目录不能靠字符串前缀继承授权。

## 7. 状态归属、skill 与受管命令

### 7.1 状态归属

| 状态 | 归属及规则 |
|---|---|
| 发布包、激活记录、授权、缓存索引、生命周期事务 | 执行宿主实例，遵循现有 `paths::instance_home()`；版本目录不可写业务状态 |
| 卡片、项目偏好与归档、项目合并锁/观测 | 经授权项目的插件数据目录，安装/更新不删除 |
| 同用户整机并发窗口/峰值配置与共享租约 | 保留现有跨项目、跨实例的专用共享配额域；这是有意共享，不是实例泄漏 |
| 常驻项目登记与后台服务引用 | 宿主管理，插件通过能力接口请求，不直接改宿主登记文件 |
| 桌面 UI 缓存 | 客户端实例，按宿主、发布摘要和版本绑定；不是运行授权 |

程序安装及实例私有状态必须隔离，但本次不将既有整机限流改成实例各自一份。共享配额的位置由宿主作为显式运行上下文传入，与实例根分开；不通过重写 `HOME` 达成隔离。配置和租约必须使用同一配额域；不能复制活锁，不能在无法定位共享域时静默创建独立预算池。共享域不可用时阻止新自动任务并报告原因，不影响只读看板。

多个实例修改同一共享配置须串行或检查修订号；该配置的迁移与回退也纳入更新协调。共享配置/租约格式必须能被仍运行的其他实例版本兼容读取和维护；若新格式不能共存，阻止本次激活并列出需协调停用的实例，不只锁住当前实例就迁移全机共享状态。不能仅靠文件时间猜测其他实例已退出。

两份实例不能并发写同一项目的看板数据：项目运行所有权须有互斥锁；持有者信息供用户定位，不能抢占活跃持有者。维护期间由宿主保持所有权，后端重启不产生接管空隙。

### 7.2 skill 与依赖

从版本目录发现插件拥有的 skill，不复制到用户全局目录；只对已授权项目的后续会话提供。发现缓存随插件状态失效，新会话拿到匹配版本的完整目录与文件路径；旧会话保留原上下文。

既有 Project → User → System 的普通 skill 排序不因此改变。插件托管 skill 单独绑定来源；同名自定义/旧副本不能被当成发布包中的匹配 skill。发现同名冲突时显示路径与来源，不覆盖或删除用户文件；冲突解决前阻止自动看板任务，可继续普通聊天和只读查看。

Superpowers 看板是上游工作流的消费者，不自动把整套 Superpowers 塞入主程序或静默下载安装。发布清单列明必需 skill/宿主工作流能力及支持范围；缺失或不兼容时展示依赖诊断，允许安装和查看数据，但不启动相关自动任务。依赖的安装、授权另行确认。

### 7.3 受管命令和版本绑定

宿主提供通用插件 CLI 启动能力，通过受管解析入口定位程序，不依赖用户 PATH、不修改全机 PATH。具体命令拼写由协议子 spec 固定；必须能表达插件 ID、已绑定项目、版本代次和原样参数数组，不通过字符串拼接 shell 命令转义。

会话记录插件发布摘要、激活代次和执行宿主身份，恢复会话也要恢复并检查绑定。skill 中的调用通过此入口；插件内部发起的业务调用同样经过宿主授权。宿主自管的绝对启动入口及上下文随会话提供；`--state-dir` 不能默认为 worktree cwd 而落到另一块看板。

旧绑定在版本切换、停用、卸载或重连到不同宿主后被拒绝，返回需要新会话/重新启用的明确错误，不悄悄转发到新程序。普通 shell 或同用户程序仍可读写其 OS 权限允许的文件；版本绑定保证受管调用一致性，不宣称阻挡恶意模型任意绕开 shell、直接运行历史二进制或修改文件。

## 8. 通信协议与页面能力

区分执行宿主扩展 API、桌面界面 API、插件内部业务协议。前两者稳定版本化；后者由完整发布包协调。连接需握手协商，未知必需能力明确拒绝。

界面最小能力：获取已授权项目/主题/语言/宿主能力；调用自己的后端；订阅/取消事件；请求打开范围内的会话；使用通知/确认。跨项目看板选择使用宿主发放的项目句柄，不接受任意文件路径。

宿主不提供任意 RPC、任意文件访问或 shell 执行后门。宿主转发插件请求前检查授权；后端/driver 的启动会话动作也必须检查能力和暂停门禁，不能只校验 iframe。

请求带协议版本、关联 ID 和代次；定义结构校验、消息体/并发/频率上限、超时、错误类型、取消和日志脱敏。通知/确认弹窗需限制频率，不能使主窗口失去控制。前端性能故障可关闭面板；隔离不承诺 WebView CPU/内存硬配额。

读操作允许显式重试；写操作不得因超时、断线或面板重载自动重放。宿主桥/插件业务为写操作提供幂等请求标识及结果查询，无法判断时提示“结果未知”并刷新核对，不重复入队、启动或合并授权。

取消只表示停止等待或在提交前取消，不承诺撤销已提交的写操作。卸载 frame、项目切换、宿主切换与授权失效时关闭旧通道和订阅；已提交操作仍在原绑定作用域完成，绝不能落到新项目。事件带修订/序号，重连先取一致性快照再续订，不能仅靠丢失事件推导真实状态。

面板关闭不等于停止调度；停用项目不等于卸载；卸载不等于清除业务数据。

## 9. 生命周期、更新与恢复

### 9.1 状态与并发

区分包状态（暂存/已安装/激活中/可用/恢复失败）和项目状态（未授权/已启用/暂停准入/停用/故障）。界面同时报告程序已安装、项目是否可用与后端健康，不用一个 `enabled` 布尔表达全部含义。

同一实例的同一插件只能有一个生命周期写事务。多个桌面、CLI、watchman、daemon 通过执行宿主同一权威记录串行协调。项目内 supervisor 文件、功能开关和常驻引用是可修复投影，不是授权来源。持久化事务在宿主启动时先恢复，再开放插件准入。

### 9.2 更新过程

自动检查但不静默切换。用户可下载/验证/暂存；旧文件不可原位覆盖。首版每实例一个激活版本，所有启用项目一起协调。

激活过程：

1. 校验新包、执行宿主兼容性、发起更新的桌面兼容性（若有）、依赖、权限变化、剩余磁盘；获取事务锁并记录旧代次/新目标。其他旧桌面可在切换后被标为不兼容，不得永久阻塞宿主更新。无桌面的 CLI 安装/更新只检查执行宿主，后续连接的桌面独立检查界面 API。
2. 原子建立排空屏障：阻止新自动任务、新插件相关模型回合和新的外部写操作，记录屏障前已接纳的回合/操作。已有回合的旧绑定及其必要业务调用、完成状态报告、锁释放可继续；不得在回合尚未结束时统一封死 CLI。只读查看可继续。
3. 等待屏障前已有操作、关联模型执行回合和合并操作结束。活动口径按宿主回合/操作记录，不按卡片 `Running` 状态猜测；等待工具审批的未结束回合仍算活动。空闲会话不是活跃回合，未执行队列保留，不等待队列被消费完。已登记的回合退出后不得借旧凭据开启下一回合。
4. 超时或用户取消则保持旧版本、恢复旧准入，不强杀任务；界面列出阻塞项目/回合。用户如要中断任务，走现有显式取消流程后重新检查。
5. 所有旧回合和操作结束后，关闭剩余旧写/CLI 准入，暂停 supervisor/driver/watchman 对该插件的重启，停止旧服务并确认退出；所有启用项目保持维护所有权，释放/确认旧代次资源；关闭旧界面通道。不得为重启释放项目所有权而让其他实例趁隙接管。
6. 在仍关闭准入的状态下，备份并执行必要迁移，记录待提交版本/代次及项目投影；仅允许持有事务维护凭据的宿主启动候选服务并检查全部项目健康。候选版本不是公共激活版本，客户端和普通 CLI 不可使用。
7. 全部成功后原子提交新激活版本与代次，再刷新界面、新会话 skill 发现和各项目投影并恢复准入；刷新完成前不开放相关业务请求。

所有阶段均持久化进度；崩溃重启后按事务记录恢复，不允许 supervisor 抢跑旧版本。备份包含受影响项目数据、实例配置、共享配置的修订信息；不复制 socket、PID、活锁等瞬态资源。

### 9.3 迁移与失败

迁移是已验证新版本的显式受管操作，不是安装钩子。声明输入/输出格式、超时、所需空间，维护锁内幂等运行或从备份重做。多项目迁移任一失败则不能部分恢复新版本调度。

只有所有已变更数据都能安全恢复，才整体回退并恢复旧准入；共享配额配置回退须确认修订未被其他实例更新，不能覆盖别人的新设置。不能安全恢复时进入“恢复失败”，保留数据/备份并关闭自动执行，提供日志及人工恢复说明，不假装已经回滚成功。

旧会话不热替换 skill；后续插件操作经受管入口返回过期绑定提示，用户建立新会话。已无活跃回合的旧对话可查看、继续普通聊天，但不能被后台调度直接复用旧看板绑定。

旧版本清理需检查事务、运行进程、恢复备份和引用，不能简单只保留最新包或删除仍需读取的 skill 文件。保留策略提供可见空间占用和用户清理入口，不自动删除业务数据。

## 10. 远程连接与多客户端

包安装、项目授权、程序运行和激活代次由执行宿主管理。安装/更新/卸载界面明确展示目标宿主；桌面只缓存 UI，不把本地 PATH 程序当成远端插件。

桌面从官方源或经认证宿主取得匹配的完整平台包，独立验证发布元数据及完整包摘要，再仅从中加载静态 UI；不运行包内远端平台二进制。这一首版方案允许下载冗余字节，避免引入另一套独立 UI 版本分发系统。

缓存键包含执行宿主身份、ID、版本、包摘要和激活代次绑定。静态字节可去重，运行通道不可共享。桌面还要检查自身界面 API 兼容性；远端已激活但本地不兼容时显示升级提示，不回退使用别的 UI 版本，不妨碍远端已有合法任务继续运行。

连接切换/中断立即失效旧通道。重连从宿主权威状态握手并核对版本后重新建立，不能复用未确认的写请求。无匹配缓存且离线时显示无法加载，不加载任意旧资源。

更新必须让已连接客户端确认关闭旧代次页面；无法取得确认时由执行宿主撤销旧通道。断线客户端重连后才可参与当前代次，不因一个离线桌面永久阻塞更新。

远端认证不是插件发布信任。被连接的宿主不能让桌面加载任意网页或绕过官方签名；执行宿主自身的访问控制继续生效。

## 11. 旧安装迁移与兼容

迁移探测规则由经验证发布清单声明，数据兼容转换由已验证插件的显式迁移能力提供；宿主实现通用探测/备份/接管协议，不新增按看板 ID 判断的迁移业务分支。探测仅限用户提供或实例已登记的项目及已知技能根，不递归扫描用户磁盘。

检测旧 PATH 程序、项目 supervisor、用户/项目 skill 副本、常驻登记及原功能开关，列出来源和关联项目。不执行未知旧程序来证明其官方身份，也不把已有开关解释为新能力授权。

用户显式选择接管后：获取并验证正式包 → 备份旧记录 → 停止新任务并排空旧操作 → 停止旧受管进程 → 检查数据兼容性和同名 skill 冲突 → 用户确认项目/后台/全局配额权限 → 原子建立新登记并切换 → 健康检查。失败恢复可恢复的旧记录；未知格式不原地猜迁移。

保留卡片 ID、状态、队列次序、项目设置及会话跳转关联；旧全机配额与活锁不复制为每实例独立池。已有数据由新版本声明可读或显式迁移，否则阻止接管。

不覆盖/删除用户自定义 skill、不删 PATH 上用户安装的旧程序；说明其已不再被托管。插件自有旧副本也只有在确认归属且用户同意后归档。接管后项目不能同时运行新旧两个看板进程。

旧版 `plugin/install` 的“注册并启用”语义不得在新 UI 中冒充下载。通过版本化管理接口区分包安装、项目启用和常驻授权；不支持的旧客户端收到明确错误/升级提示，不能被旧 RPC 绕过授权。

旧看板专属 UI、TUI、系统 skill、实验开关入口与帮助文本在迁移完成后删除或迁为通用插件入口；不保留一个可绕过新管理流程的暗门。

## 12. 故障、停用与卸载

错误必须区分：签名/信任失败、平台/API 不兼容、依赖冲突、未授权、代次过期、后端离线、超时结果未知、迁移失败。返回可定位错误码、插件/宿主/项目及安全日志入口，不泄漏令牌或敏感文件内容。

页面失败由宿主外壳显示重载入口；后端失败显示不可用，不伪装空列表；重启有限退避，达到阈值关闭新自动任务并报告。业务任务失败仍按插件业务状态处理，不能被安装失败逻辑吞掉。

停用、撤销权限和卸载复用更新的准入/排空/维护协议。用户可等待或显式取消任务，不静默杀掉模型执行。停用后关闭页面业务通道、撤销后续托管 skill/命令准入；保留宿主管理页和数据。

卸载要求宿主知道该插件的全部授权项目并全部完成停用，再移除托管运行入口、skill 来源、实例安装记录和可删除包/缓存。项目目录丢失或不可达时保留“待清理”记录及可见错误；不能宣称完全卸载，也不能让残留 supervisor 后续重启程序。

卸载默认保留项目数据和可恢复配置。清除数据列明项目、范围和备份，单独确认；共享配额配置、其他实例使用的租约和共享后台服务不在默认删除范围。后台引用按请求者释放，只在没有其他使用者且用户同意时移除宿主级常驻服务。

## 14. 分期、协议子 spec 与审阅门槛

该目标跨资源隔离、分发管理和业务迁移，不作为一个无检查点的大实施任务。

1. **技术验证**：先证明 Tauri 正式构建的隔离加载、桥与原生权限边界；产出可执行验证及结论。
2. **宿主协议子 spec**：固定包/清单 schema、两端 API/桥、托管命令绑定、权限及项目句柄；审阅后实现最小第二插件，证明通用性。
3. **分发与生命周期子 spec**：固定签名元数据、信任更新、管理 RPC、持久化状态机、更新/恢复及配额协调；审阅后实现并做故障注入。
4. **看板迁移子 spec**：映射 UI/设置/TUI/skill/工作流依赖、旧数据与进程、远程版本资源；审阅后迁移业务，不改变既有卡片与整机配额语义。
5. **正式验收**：清除宿主看板专属路径，跑完 A01–A20，发布文档和目标平台包。

子 spec 不能推翻本设计的安全、授权和独立发布边界；需要改变这些决策时先重新确认。首版发布必须覆盖完整目标，不以界面暂时内置或仅本地可用替代。
