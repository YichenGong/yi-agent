# Desktop 子 agent 执行面板重新设计

日期：2026-11-07
状态：对话示意方案已获用户确认；书面规格待用户复核，尚未实现。
分支：`feat/desktop-subagent-trace-redesign`

## 1. 目标与范围

把 desktop 右侧「子 agent」从平铺日志查看器改为「任务列表 + 执行时间线」。优先改善信息层级、窄栏阅读、实时跟随与下钻导航，不增加后端协议或新依赖。

保留会话详情栏的三个 Tab、宽度持久化与拖拽（260–720px，默认 360px）、现有消息投递与两阶段取消协议。此栏当前只在 desktop 显示，本次不新增手机入口，不修改 Git Diff 或后台进程的内容布局。

非目标：完整工具 stdout 获取、耗时/时间戳/成本推断、搜索筛选控制台、任务重排、虚拟列表、主对话样式重构、独立 App 打包。

## 2. 当前事实与约束

- `desktop/src/components/SubagentRail.tsx`：厚边框卡片、英文状态、目标单行截断。
- `desktop/src/components/SubagentTrace.tsx`：默认摘要，二次点击才显示轨迹；段落平铺；消息需先打开输入框；发送失败仍会清稿。
- `desktop/src/components/ThreadDetailPanel.tsx`：负责外框、Tab 和返回列表。
- `desktop/src/lib/subagents.ts`：连续 assistant_text 合并，工具调用与结果各自成块。
- `desktop/src/hooks/useSessionState.ts`：持有选择、读取快照和 watch；目前 openDetail 总是重设单元素 detailStack，不能依赖注释所称的已有导航栈。
- `AgentTraceRow` 只有 eventId/taskId/kind/payloadJson；当前展示读取 name/summary/is_error/note，没有稳定的工具调用关联键与时间戳。

因此：工具调用与结果保留为独立的、有类型的时间线事件，不根据相邻位置猜配对；结果只能称「结果摘要」，不能称完整输出。状态完全来自服务端，不由最后一个工具结果推断任务完成。

## 3. 视觉结构

采用中性底色、细分隔线、少量圆角。沿用现有语义主题 token，状态色提供深浅主题可读的局部 token，不直接使用只适合深色的浅蓝/浅红文字。状态始终带文字，不只靠颜色。

### 3.1 任务列表

```text
┌─────────────────────────────────────┐
│ 子 agent       后台进程     Git Diff │
├─────────────────────────────────────┤
│ 子任务                    2 个运行中 │
│                                     │
│ ● 检查登录流程                    › │
│   正在读取 auth/session.ts          │
│   运行中                            │
│ ─────────────────────────────────── │
│ ● 补充接口测试                    › │
│   正在执行 npm test                 │
│   运行中                            │
│ ─────────────────────────────────── │
│ ✓ 梳理现有组件                    › │
│   已完成                            │
└─────────────────────────────────────┘
```

- 保留服务端行顺序，不按状态自动排序，避免运行时跳动。
- 目标最多两行，完整目标可在详情阅读；缺失或空白时显示 taskId。
- 非终态显示 lastStep，缺失时「等待进展」；终态不再显示旧的当前步骤。
- 表头活动数统计已知非终态（包括等待子任务），文案使用「进行中」，避免把 waiting_for_children 说成正在执行。
- completed → 已完成；completed_no_changes → 已完成，无变更；failed → 失败；cancelled → 已取消；running → 运行中；waiting_for_children → 等待子任务。未知状态保留原值，使用中性色。
- 整行可点击，hover/focus 清楚，保留 aria-current 语义。
- 空态使用小标题「暂无子 agent」和说明「委派子任务后，执行进展会显示在这里」，不提供虚构的创建按钮。

### 3.2 详情

```text
┌─────────────────────────────────────┐
│ 子 agent       后台进程     Git Diff │
├─────────────────────────────────────┤
│ ‹ 全部任务  /  父任务（有则显示）    │
│ 检查登录流程                        │
│ ● 运行中                  task-a31f │
│ 正在读取 auth/session.ts            │
├─────────────────────────────────────┤
│ 执行轨迹                            │
│ ○ 我先检查会话恢复和鉴权入口。      │
│ │                                   │
│ ├─ 读取文件                         │
│ │  src/auth/session.ts              │
│ │                                   │
│ ├─ 结果摘要                    展开 │
│ │  已读取文件                       │
│ │                                   │
│ ○ 找到一处可能导致重复刷新的逻辑。  │
│ │                                   │
│ ● 等待新的执行进展…                │
│                                     │
│                    [ 回到最新 ↓ ]   │
├─────────────────────────────────────┤
│ 向这个 agent 发送消息…              │
│ 停止任务                     发送 ↑ │
└─────────────────────────────────────┘
```

- 固定导航与任务摘要，时间线是唯一主纵向滚动区，底部消息区固定。子任务区放在滚动内容内，避免多个固定区挤没正文。
- 进入后立即展示时间线，删除整体「展开轨迹」开关和摘要/全文二级视图。
- 标题自然换行，taskId 次级等宽显示、可选择复制，长 ID 断行不挤压标题。
- assistant_text 复用项目 MarkdownText；连续文本仍按现有规则合并，不额外套聊天气泡。
- tool_call 卡片显示工具名与服务端摘要；已知工具可用中文动作辅助标签，但未知工具保留原名。不得把摘要再当 JSON 输入推断新信息。
- tool_result 显示「结果摘要」及首行预览，超出 3 行或 240 字符时默认折叠，可展开收到的全部摘要。is_error 为真时，错误标识与错误首行无需展开即可见；完整摘要仍可折叠。
- state_note 使用低强调注记；未知事件提供事件类型与可展开原始文本。损坏 JSON 或字段类型不符时也保留原文入口，不静默丢弃。
- 长行使用局部换行/代码区横向滚动，不能使整栏横向溢出；长结果只参与主滚动，不增加嵌套纵向滚动区。
- 保留以 eventId 派生的稳定 key 和按值 memo 的叶子边界；流式追加不重挂已定稿块，不重置折叠状态。

## 4. 实时更新与导航

### 滚动

首次进入任务，快照加载后定位最新；此时进入跟随态。用户距底部超过 64px 时暂停跟随；回到 64px 范围内或点击「回到最新」恢复。跟随使用即时滚动而非逐事件平滑动画。

暂停时出现「回到最新」浮动按钮，不占正文流；新事件到达不抢滚动。展开/收起摘要以当前阅读位置为准，不因内容高度变化误判为新事件并拉到底。切任务重置跟随状态及折叠状态，不沿用前一个任务的滚动位置。

### 导航

「全部任务」始终回到列表。若当前 row.parentTaskId 能在当前会话 railRows 找到对应任务，增加单级可点击父任务入口；根任务或父元数据缺失时不显示虚假路径。父级入口显示目标，过长时截断并提供完整标题。无需新增导航历史栈。

当前任务的直接子任务使用「子任务 N」可折叠区，默认展开紧凑行，行内显示状态与目标；进入后仍能通过父入口返回。行数不限，由主滚动区承载。

### 数据与竞态

继续使用 trace/read、trace/watch、trace/unwatch。补充本地读取状态 loading/ready/error：读取中显示「正在读取执行轨迹…」；ready 且为空显示「暂无执行轨迹」；读取失败显示内联错误与重试，不伪装成空态。

读取/订阅回包必须核对当前 threadId、taskId 和请求代际，切任务、切会话或关闭后旧快照不得覆盖新视图；只有当前选择可以创建或保留 watch。沿用并验证后端对单线程 watch 的替换语义，避免盲目增加会解除新订阅的旧 unwatch。此处只做本次导航所需的局部接线与竞态保护，不重构会话系统。

## 5. 消息与停止操作

- 直接显示紧凑 textarea 与发送按钮，取消「先点发消息」步骤。
- Enter 发送、Shift+Enter 换行；复用 IME 守卫，中文选词回车不发送。空白消息或发送中禁用发送按钮。
- 仅成功发送后清稿；失败显示内联可读错误、保留草稿和输入焦点。请求完成必须校验任务/会话身份，不能清除新任务的草稿。
- 草稿按 threadId + taskId 在当前前端会话内保存，切任务再回来仍保留；不写磁盘，不引入全局草稿系统。可由详情面板上层持有小型映射，切会话不得串稿。
- 消息操作不与「终态不可恢复」混淆：是否允许向终态发消息沿用当前服务端裁决，不自行宣布支持重启。只有 row.finished 明确为真时隐藏停止按钮；未知状态不臆断终态。
- 点击停止仅请求 cancel/preview，原位显示确认框。展示 preview.taskIds 的受影响任务数量，提醒可能包括子任务；确认时携带原 token 调 cancel，不绕过预览。
- 确认和预览均有 pending 状态防重复提交；可放弃确认。token 仅属于原任务及预览周期，换任务/会话或过期即失效；过期后要求重新预览。
- token 的有效期按 preview.expiresInSecs 从收到响应时保守计时，服务端最终校验仍为权威。确认失败展示错误，不显示「已取消」；成功回执只显示「取消请求已提交」，任务终态以服务端通知为准。
- 无连接时消息/取消操作必须失败并展示错误，不能把可选链返回 undefined 当成功。

## 6. 组件职责

- SubagentRail：表头、任务列表、空态。
- SubagentTrace：任务头部、时间线、子任务区及动作区组合；必要时拆出专用 TraceTimeline/TraceEvent/TraceComposer，避免把所有状态塞进单文件。
- 共享小型状态呈现 helper：中文标签、终态与语义色，列表/详情/子任务一致。
- subagents.ts 或专用纯函数模块：安全解析 trace 事件与折叠，不在渲染层重复解析，保留旧函数消费者兼容或一次性迁移所有调用点。
- ThreadDetailPanel/App/useSessionState：父级入口、读取状态、任务草稿与现有 RPC 连接；不承担事件排版。

## 7. 验收

自动测试至少覆盖：

1. 列表中文状态、活动计数、空态、终态不显示旧步骤、未知状态与长目标。
2. 默认可见时间线；连续文本合并、Markdown、未知/损坏事件不丢失。
3. 调用和结果不猜配对；长摘要可展开；错误首行默认可见；定稿 DOM 与折叠状态在流式追加时保留。
4. 首次定位、在底部跟随、上翻不抢滚动、回到最新、切任务重置。
5. 任务列表/直接子任务/父级返回、父元数据缺失安全回退。
6. loading/空态/error/retry 不混淆；快速切任务与关闭后的旧回包不污染当前视图。
7. 发送失败留稿、成功清稿、IME/空白/重复发送、切任务和切会话不串稿、未连接不假成功。
8. preview 先于 cancel、受影响数量、放弃、有效期、防双击、失败不误报成功、已结束任务无停止入口。

执行 `cd desktop && npx tsc --noEmit && npm test && npm run build`。提交实现前按项目要求执行 `cd yi-agent-rs && cargo fmt --all && just ci`，合并后再次执行 just ci。纯设计文档提交免 CI 与单测。

视觉验收使用真实组件和项目 CSS，检查深浅主题 × 260/360/720px × 小/标准/大字号；覆盖长中文目标、长路径、长代码、空轨迹、错误、多个子任务，验证无整栏横向溢出、主内容可滚、操作区可达、键盘 focus 清晰。浏览器可以用于实现后的验收，但不启用用户拒绝的 visual companion。无法执行原生 WebView 验收时明确登记未验，不以单测代替视觉结论。

交付时同步更新 `docs/project-management/desktop.md` 与模块索引计数，提供实际命令结果；未完成视觉验收不得笼统宣称全部验收通过。
