# TUI 输入区改造：可见的 3 行输入卡片

日期：2026-11-01
状态：已确认，待实施

## 1. 问题

用户报告两个现象，实为同一块代码的两个缺陷。

### 1.1 输入条的浅灰背景看不见了

输入条的背景在 `65d78226`（2026-10-31，「浅色终端主题改造」）里从硬编码
`Color::Indexed(240)` 换成了主题槽 `theme.bg_raised`。

| 版本 | 色值 | 与假定页面底色 `#1e1e1e` 的对比度 |
|------|------|-----------------------------------|
| 改造前 | `Indexed(240)` = `#585858` | 2.34 |
| 改造后 | `bg_raised` = `#2a2a2a` | 1.16 |

`bg_raised` 当初刻意选成「刚好比底色亮一点」，用于弹窗卡片的描边感。放到输入条
上就是几乎与页面同色的一条带子。

用户的实际终端是 Ghostty，默认背景 **`#282c34`**（不是代码假设的 `#1e1e1e`）。
`#2a2a2a` 对 `#282c34` 的对比度只有 **1.025** —— 等于完全同色。这才是「彻底
看不见」的直接原因。

### 1.2 输入区只有 1 行高

`compute_input_height()` 直接返回换行后的行数，空输入时等于 1。它上方另有一条
独立的 1 行纯背景空隙（布局里的 `chunks[4]`），与输入条不是一体，视觉上是两块
东西。

### 1.3 现有前缀污染复制

输入区第一行渲染 `"> "`，续行渲染两个空格（`PREFIX_LEN = 2`）。用户用终端原生
选中复制时，这些字符会一起进入剪贴板。Ghostty 的
`clipboard-trim-trailing-spaces = true` 只裁**行尾**空格，行首空格原样保留。

## 2. 目标

1. 输入区是一个**看得见**的淡灰卡片。
2. 输入区固定 3 行：上留白、中间输入、下留白。内容变长时扩中间，上下留白保留。
3. 复制输入内容时**不带行首空格**。

## 3. 非目标

- 不新增复制快捷键。用户明确要求只用 Cmd+C / Cmd+V。
- 不改上下留白行。用户明确表示「不框选上下两行就行」。
- 不改弹窗卡片、trace 面板的背景（它们继续用 `bg_raised`）。

## 4. 设计

### 4.1 新增主题槽 `input_bg`

`TuiTheme` 新增 `input_bg`，与 `bg_raised` 分开。理由：`bg_raised` 还服务弹窗卡片
和 trace 面板，跟着一起变重会连带改变那些界面的观感。

| 主题 | 值 | 对页面底色的对比度 | 正文可读性 |
|------|-----|-------------------|-----------|
| Dark | `Rgb(0x58,0x58,0x58)` | 2.34（对 `#1e1e1e`） | `#e4e4e4` = 5.60:1 |
| Light | `Rgb(0xb9,0xb9,0xb9)` | 1.96（对 `#ffffff`） | `#1f1f1f` = 8.40:1 |

深色取 `#585858` 是用户的明确要求「跟旧的一样」，与旧 `Indexed(240)` 逐字节同值。

浅色**不能**照搬 `#585858`：旧版在浅色终端上就是这条深灰带，上面黑字只有
2.32:1，正是 `2026-10-31-tui-light-terminal-theme-design.md` 修掉的可读性缺陷。
`#b9b9b9` 在白底上的视觉权重与深色 `#585858` 在深底上相当（1.96 vs 2.34 同一量
级），正文仍有 8.40:1。

### 4.2 输入区固定 3 行

高度 = 内容行数 + 2，内容上限 6 行，故最高 8 行。

```
内容行数 1 → 总高 3
内容行数 3 → 总高 5
内容行数 6 → 总高 8
```

留白行是**纯背景、无字符**的行。它们与内容行同色，整块是连续的淡灰色卡片。

`compute_input_height()` 改为返回 `wrapped_lines + 2`。

### 4.3 删除独立的 `chunks[4]` 空隙

新卡片自带上方留白，再保留一条独立空隙会显得松散。布局约束从 6 块变 5 块：

| 改造前 | 改造后 |
|--------|--------|
| `[0]` history | `[0]` history |
| `[1]` popup | `[1]` popup |
| `[2]` status | `[2]` status |
| `[3]` queued | `[3]` queued |
| `[4]` blank gap（1 行） | —— 删除 |
| `[5]` input | `[4]` input |

净代价：历史区少 1 行（原本 1 行输入 + 1 行空隙 = 2，现在 3）。

### 4.4 保留 `> `，去掉续行缩进

用户要求保留 `> ` 提示符，同时不接受续行那两个用于对齐的空格。

- 第一行：输出 `"> "`，文字从第 2 列开始（`first_avail = width - 2`）。
- 续行：**不输出任何前缀**，文字从第 0 列开始（`cont_avail = width`）。

复制结果形如：

```
> 第一行内容
续行内容
再续行内容
```

只有最开头一个 `> `（`>` + 空格共 2 字符，用户需要它作为输入区标识），续行没有
任何行首空格。

视觉上左边缘参差 2 列（首行缩进、续行顶格），这是为复制干净付出的代价，已向用户
说明并接受。

**限制**：复制时不框选上下留白行；框选则那两个空行会进剪贴板。这一点用户明确
接受（「我不框选上下两行不就行了」）。

### 4.5 `Ctrl+C` 提示也占 3 行

提示文字渲染在中间行，上下照样留白，避免按下 `Ctrl+C` 时高度从 3 塌到 1 造成
画面跳动。

### 4.6 光标

保持现有 `Modifier::REVERSED`，不引入固定色块。REVERSED 由终端按自身背景解析，
深浅两套主题都可见。

## 5. 数据流

```
InputLine.buffer ──► wrap_input_buffer (PREFIX_LEN=0) ──► Vec<Line>
                                                             │
                            compute_input_height = lines+2 ───┤
                                                             ▼
                                        Paragraph.style(bg=input_bg)
                                                             │
                                    首行/末行补空白行 ◄───────┘
```

## 6. 验收

### 6.1 单元测试

| 测试 | 断言 |
|------|------|
| `input_stripe_uses_input_bg` | 深/浅两套主题下，输入区 padding 格子的 `bg == theme.input_bg`，且 `input_bg != bg_raised` |
| `input_bg_is_visible_against_page` | `input_bg` 对假定页面底色的对比度 >= 1.9（深/浅都验） |
| `body_text_on_input_bg_is_readable` | `fg` 对 `input_bg` >= 4.5:1（深/浅都验） |
| `compute_input_height_*` | 空输入为 3；内容 N 行时为 N+2；上限 8 |
| `wrapped_input_keeps_only_the_first_prefix` | 首行以 `> ` 开头；续行不以任何空白开头 |
| `input_card_pads_one_blank_row_each_side` | 渲染 3 行区域，第 0 行与第 2 行无字符且背景为 `input_bg` |

### 6.2 手工验收

1. 启动 TUI，确认输入区是 3 行高的连续淡灰卡片。
2. 输入长文本，确认上下留白仍在，只有中间扩展。
3. 框选中间输入行 + Cmd+C，粘贴到编辑器，确认**无行首空格**。
4. 按下 Cmd+V 粘贴多行文本，确认内容完整。
5. 按 `Ctrl+C`，确认提示行不改变卡片高度。

## 7. 风险

| 风险 | 缓解 |
|------|------|
| 去掉 `> ` 后用户认不出输入区 | 淡灰卡片 + 上下留白提供足够区分度 |
| 历史区少 1 行 | 属于用户明确要求（3 行卡片）的必然代价 |
| 浅色主题灰条过重 | `#b9b9b9` 经对比度验证，正文 8.40:1 |
| 布局索引改动影响鼠标命中测试 | `chunks[5]` → `chunks[4]`，全部引用点同步修改 |
