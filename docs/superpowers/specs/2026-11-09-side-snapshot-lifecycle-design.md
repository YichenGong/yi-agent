# 一次性对话快照旁问设计

日期：2026-11-09
状态：设计已写，待用户审阅；未实现，未编写对应实施计划。

## 1. 用户确认与目标

本规格依据本轮用户明确确认的行为：

> side 只能读当前对话；fork 一份内容，用户针对 fork 的内容提问；每个 session 只能开一个 side session。旁问基于原来的快照，退出 side 直接销毁对应环境，不保留；下次进入是全新的环境。

旁问是主任务运行期间的**一次性快照问答**，不是只能查看日志的页面，也不是在后台保留、可以恢复的第二条任务会话。

用户在主任务进行到一半时输入 `/side 现在做到哪了`：主任务不被中断；旁问基于进入时已提交到当前对话的内容解释进展。用户可以在本次旁问内连续提问。退出后销毁；再次进入重新取当时的最新快照。

“只读”约束的是**信息来源与副作用**，不是“不能提问”：允许向模型提问，但不允许旁问继续执行父任务、修改父状态或读快照之外的资料。

## 4. 产品行为

### 4.1 进入

- 入口保持 `/side [问题]`，`/btw` 为别名，不增加常驻旁问模块。
- 来源只允许用户当前选中的父 session。前端在发请求前捕获其完整身份；异步过程中切换到其他 session，迟到结果不能打开或污染新 session。
- 输入命令不发给父模型，也不先打断父 turn。
- 从主视图进入且没有活环境：创建一次快照与一个独立问答环境。空问题只创建和进入，不发空的模型请求。
- 本旁问已经打开时，重复进入/重复点击只定位已有环境，不能重复创建或刷新快照。
- Closing 或清理未排空时显示“上一条旁问正在退出，请稍后重试”，不并行建立第二条，不自动后台排队创建。

### 4.2 问答

- 在本次环境内可连续提问；每轮使用同一份父快照，加本旁问已经受理的问答历史。
- 主会话后续进展、compact、模型更新不追溯改变快照。
- 界面说明：“基于进入时的对话快照；不跟随主任务更新；退出后丢弃。”避免裸写“只读”让用户误以为不能问。
- 当用户问快照之后的进展、未包含的文件事实，模型明确说明不知道；提示退出再进入取得最新对话快照。不能用工具查资料补齐。
- 快照反映稳定历史，不保证包含主模型尚未提交的逐字输出或未完成工具结果；不得把“不在快照中”解释成“任务没有做”。
- 旁问自己的模型与输出 token 仍正常计费，使用现有准入、限流和预算，不承诺免费，也不绕过父 provider 的总并发限制。

### 4.3 退出

以下动作从 side 离开时都具有“退出并销毁”语义：

- `/back`、返回主会话按钮。
- `/side-close`（保留兼容别名，不再提供另一种“返回但保留”行为）。
- 点击侧栏切到主会话/另一普通 session，或切到另一个项目/宿主。
- TUI 的应用退出、桌面/手机前端真正卸载且可发送退出请求时。
- 父 clear/delete 等使来源失效、关闭实验开关、宿主退出。

退出是明确的破坏性意图，不再二次询问“是否停止当前回答”。帮助/按钮说明必须提前写清“退出会停止回答并丢弃本次旁问”。Esc/Stop 仍只停止本旁问当前回答，不代表退出；停后可以留在本次环境继续问。

本地界面立即离开，关闭输入与旧环境的提交通路；宿主收到退出意图时原子标记 Closing、取消本旁问，再异步排空工作与释放资源。不能等模型自然回答完；不能只隐藏 UI 后让它继续跑。

关闭本旁问不能关闭共享 provider、主 session、主 task 或其他父 session 的旁问。“销毁环境”不是杀整个 app-server 进程。

### 4.4 再次进入

宿主完成旧环境清理后，重新进入必须：

- 分配新 `sideId` 和独立 Session/取消域/ledger/转录。
- 重新获取父会话此刻的快照与有效模型配置。
- 不恢复旧问答、旧草稿、旧用量、分页 token、滚动位置、请求去重表或 pending 首问。
- 丢弃旧环境迟到的 open、分页、提交响应与流式事件；旧退出重试也不能关闭新环境。

## 5. 快照与能力边界

### 5.1 内容范围

只复制当前父 session 中已被受理且安全可 fork 的稳定模型对话：用户消息、已提交模型回复、配对完整的工具调用及其已记录结果、对话中已经内嵌的媒体内容。

- 使用既有安全 fork 过滤，尾部未配对工具调用不得成为可执行指令。
- 父历史工具调用只作为证据，不会在旁问内重新执行。
- 独立 Session 不是普通持久 `thread/fork`：不新增侧栏 thread、不落持久问答日志、不获得普通 agent 的工作区能力。
- 附件路径、图片 URL、文件名或工具结果中的链接只是历史文本/来源标记，不授予继续打开文件或下载链接的能力。
- 已内嵌且 provider 可直接处理的媒体随快照保留；只有路径/链接而没有正文的资料不补读，回答中明确其内容未包含。不再创建附件文件副本。
- 为调用模型必需的 provider、模型、reasoning 配置沿用父创建时的有效配置；不额外读取项目文件、加载新 skills/MCP 或重新扫描项目规则。安全策略末尾追加，不因父规则要求工具而放宽。

### 5.2 无工具问答

旁问模型的 tool registry 为空：不注册文件读取、glob/grep、web_search/web_fetch、shell、write/edit、MCP/plugin、浏览器或 subagent 工具。它不是“只注册 read-only 工具”，而是**只读对话快照、无外部工具**。

执行层也要拒绝幻觉工具调用，不转发到父 registry；提示词只负责说明语义，不能代替能力边界。模型不得继承父 inbox、审批 decision channel、工具令牌或主任务控制句柄。

### 5.3 独立性与预算

- 主 session 数据不被 push/pop、清空或改写；主任务不等待旁问创建/回答/退出。
- 短临界区取稳定快照，网络、排空、清理均离开主 RPC/driver 单 task 路径。
- 继续沿用既有文本/转录预算与宿主配额，超限明确失败、不偷偷截断父历史。去掉附件副本后不把它的旧预算改成无限文本预算。
- 与[运行参数即时生效设计](2026-11-04-runtime-settings-live-apply-design.md)的关系：保留实时准入/取消及安全资源上限；这些限制不属于对话快照。旁问的父历史、模型身份和父提示词则在创建时冻结，不再挂会重新扫描技能或改变问答信息来源的动态 prompt adapter；这覆盖该设计中旁问动态提示词的部分，不回退主会话、daemon 或其他 agent 的热更新行为。
- 每次退出后，本环境保留的快照与问答引用必须释放；不能借 metrics、日志或缓存保留正文。

## 6. 生命周期、退出协议与竞态

### 6.1 不变量

资源状态：`Creating → Open(Idle | Running | Failed) → Closing → Closed`。不再有可以恢复问答的 Hidden 状态。

- `(hostInstanceId, parentSessionId)` 同时最多一个 Creating/Open/Closing 环境。
- 未结束的模型流、转发任务、资源 owner 仍归旧环境，继续占资源槽；禁止提前释放父占位后创建第二套。
- Idle/Failed 可在本次停留内继续问。原 30 分钟“隐藏保留/续期”不是产品功能；现有有界空闲回收只可作为故障兜底，不提供恢复入口。
- 关闭一次后不可恢复；同一精确环境的退出重试幂等。

### 6.2 与现有条件关闭区分

新增面向生命周期的 `side/exit` 契约（具体 wire 类型在 plan 中落定），不能让 UI 循环调用旧 `side/close` 去猜活跃 turn，也不能泛化一个可关闭任意父旁问的无身份 force-close。

契约必须满足：

1. `side/open` 带客户端生成的入场操作标识，宿主在异步构造前把该意图绑定到父占位与环境代次；成功响应关联实际 side 身份。标识在认证客户端身份内唯一，并绑定宿主实例与父身份；同一标识换父使用明确拒绝，重试只返回原绑定结果。多个端并发进入时，各自标识绑定同一个 Creating/Open 代次，不刷新快照；其中一个有操作权限的端退出便关闭这一共享代次。若退出先于 open 到达，则先记录该标识已撤销，迟到 open 不能创建；若此时没有建立绑定，也不能据父 id 关闭另一端的未知环境。
2. `side/exit` 可以按同一个入场标识撤销 Creating；已创建时按宿主/父/side/代次精确退出。本地没有拿到 sideId 不构成留下幽灵环境的理由。
3. 退出只命中这个意图所属的一代。旧 open/exit 的重试不得创建或杀掉下一代；同父后来重新进入的操作使用新标识。
4. Closing 转换、禁止新 turn、创建代次撤销必须在同一权威生命周期屏障下成立。活跃 turn 的改变不导致本代环境退出失败。
5. 首问只有入场意图仍有效才可提交。Creating 期间返回后，迟到 open 不能自动发首问；即使创建已在宿主完成，也须销毁其实际资源，不只丢弃响应。
6. 控制通知与响应在背压下不能把资源清理无限挂起。先保证停止与资源回收，再有界投递终态；失败由客户端重新读取生命周期状态对账，不能以“通知没投递”继续保留 runner。
7. 操作映射/已退出标记有界、仅含必要身份与去重信息，不含正文；淘汰后旧操作明确失效，不能重建历史环境。

现有 `side/close` 可继续服务旧客户端的条件关闭，但新前端退出路径使用新契约。增加明确的退出能力协商标记；不能只凭旧 `side_conversation_v1` 就向用户承诺新生命周期。旧宿主缺新能力时，新入口提示需更新宿主，不回退为“返回保留”。新宿主关闭后旧客户端收到终态也不能复活环境。

### 6.3 取消与资源回收

退出必须主动取消本环境的 provider 请求/等待准入/转发任务，拒绝后续结果提交，释放会话、转录、ledger、分页快照、临时目录与句柄。本次不新增后台工具或子进程；既有运行器如果仍持有旧阻塞任务，必须由 owner 跟踪排空，不能声称 abort 已经终止不可取消的 IO。

“立即”指意图一被宿主接受就禁止继续使用并发出取消，不承诺远端供应商物理计算在同一瞬间停止。排空要使用既有有界关闭预算；超时报告 Closing/清理失败并隔离残留，不报告成功、不释放占位绕过唯一性，不影响主任务。

### 6.4 断线与后台

本规格区分**明确退出**与**临时传输中断**：

- 手机后台、瞬时 WebSocket 断开、macOS 窗口隐藏本身不冒充用户退出；不因另一只读查看端断线关闭共享环境。
- 若用户已明确退出但网络不可用，本地立即清掉可见正文并保留最小的精确退出意图；重连先补退出，不能恢复旧旁问或发旧首问。未确认销毁时不允许创建同父的新环境。
- 前端不可发送的意外死亡通过现有空闲回收/宿主退出兜底；不虚称浏览器关闭时一定能可靠传出 RPC，也不承诺断网时立即控制远端进程。
- “临时重连对账”只服务仍未退出的一次停留，不是已退出环境的恢复机制。若以后需要前端死亡立即回收，另设宿主租约方案，不在本次加入不明来源的计时阈值。

## 7. 多端与设备权限

沿用同宿主内同父共享一条旁问：桌面与手机并发打开得到同一环境；TUI 独立宿主，不假装跨进程共享内存。

- 有 Control/Admin 权限的端退出时销毁共享环境，其他端收到终态立即丢弃对应一代并提示“本次旁问已退出”。没有“最后一端离开才销毁”或引用计数保留模式。
- 任意一端退出旧环境的迟到重试不能杀掉另一端之后新建的环境。
- Observe 是既有设备授权档位，不是本次快照的只读属性。本次不扩大设备权限：普通有操作权限的用户可创建与连续提问；Observe 仍只查看已授权的已有旁问，其本地离开不授予关闭共享环境的能力。该路径不作为创建/问答的产品入口。
- 不根据手机/桌面型号推断权限，不承诺存在已经实现的设备降级 UI。
- 客户端只从当前选中父会话发起旁问；服务端复用父可见范围与认证授权。此限制不是新增的每工作区 ACL，不能把“当前选中”当成安全凭证。
- 本机关闭实验开关只清本机环境，不调用远端关闭；若当前显示远端旁问，也不应被本机 flags/set 顺带导航退出。

## 8. 三端交互与错误

- 桌面/手机：`back`、`selectMain`、项目切换和返回按钮进入同一个退出协调入口；先捕获旧身份、撤销导航意图，再返回/导航；保留最小关闭收据，不保留可续聊 store。
- TUI：`/back` 与 `/side-close` 走同一环境销毁动作。父审批键路由继续保持隔离；退出 side 不批准、不取消父审批。应用退出排空本旁问，不创建新主 turn。
- 重复退出：幂等，不多次取消其他环境。
- 退出失败：主视图显示“旁问退出尚未确认/清理失败”，允许重试精确旧退出；不恢复正文，不静默重新 open。
- 创建失败：回滚创建占位、释放资源、在父输入区域给出原因；不留下可继续的壳。
- 快照中没有所需信息：模型说明边界，不去实时读文件。
- 实验功能关闭/旧宿主能力不足：拒绝入口，不能把 `/side` 文本发给父模型。

## 9. 验收矩阵（实施完成判据）

以下均为待实现/待执行的验收，不沿用历史测试数量假装通过。

| 场景 | 必须证明 |
|---|---|
| 父长任务中首次进入 | 父不 interrupt；安全 fork 快照；旁问能解释快照内进度 |
| 连续追问 | 同一 sideId、同一父快照；主历史不含旁问问题/回答 |
| 父继续提交内容 | 现有 side 不自动看见新增消息；再次进入的新环境能看见 |
| 只读信息来源 | 注册表零工具；历史工具调用不执行；路径/URL 不触发读取或下载 |
| 空闲退出与运行中退出 | UI 离开，runner 被取消并结束，快照/转录/ledger/分页资源释放 |
| 活跃轮次变化时退出 | 精确本代仍能退出，不要求用户反复确认 turnId |
| Creating 中退出 | 首问零提交；迟到创建资源被销毁；占位正确释放 |
| 退出后立刻再次进入 | 清理未结束拒绝第二套；结束后新 sideId、新快照、无旧草稿/用量 |
| 并发重复进入 | 同宿主同父只有一个 Creating/Open/Closing 资源槽 |
| 旧响应/旧退出/旧终态迟到 | 不恢复旧环境、不跳转、不污染或关闭新环境 |
| 两端共享 | 控制端退出后两端旧环境失效；不关闭其他父/其他宿主 |
| Observe 查看端离开 | 不创建、不提问、不取消控制端的共享环境 |
| 切 session/项目 | 销毁离开的 side；来源 RPC 不误发到新 client |
| 退出时断网 | 不恢复旧正文；重连先补精确退出；未确认前无新建 |
| 手机后台/临时断线 | 不伪造明确退出；没有已退出环境的续聊恢复 |
| 主生命周期与实验开关 | 父 clear/delete、flag off、宿主退出收尾；父失败操作不误清 |
| 旧宿主 | 缺退出能力时拒绝新语义入口，说明需要更新 |
| 文案/帮助 | 没有“返回保留/继续旁问”；明确快照固定、可提问、退出丢弃 |

测试按现有模块落地：registry/runner/policy 的单元测试与真实 stdio 集成、桌面 controller/App 测试、TUI driver/输入循环测试。重点做变异验证：恢复 `back` 只换指针、给旁问重新注册 read 工具、提前释放父占位、去掉代次/入场意图检查，分别必须让相应断言失败。

真实验收需跑主任务中问进度 → 连续追问 → 运行中退出 → 重新进入取得新进展，核对父历史与运行中的资源。不只看返回按钮消失就宣称环境被杀掉。
